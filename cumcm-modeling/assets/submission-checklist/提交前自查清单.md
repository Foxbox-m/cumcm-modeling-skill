# CUMCM 最终提交前“四道门”检查清单

## 结果标签（用于记录，不替代人工判断）

- `OFFICIAL_FAIL`：违反当届官网、赛区或题面硬项，必须修复后再谈提交。
- `SKILL_FAIL`：违反 Skill 的结构、复现或交付要求，必须修复或明确降级范围。
- `QUALITY_WARN`：模型、证据、深度、视觉或页数存在需要人工判断的风险，不是自动否决。
- `MANUAL_CHECK`：机器无法证明的数学质量、结果真实性、视觉可读性、匿名细节或平台状态，必须人工核对。

这些标签只记录审计发现，不声称机器证明数学质量或替代最终责任人的判断。

## 门禁一：正确性与复现性门（Correctness & Reproducibility）
- [ ] 论文正文中引述的所有关键数字与支撑材料代码实际运行输出 100% 一致；
- [ ] 支撑材料中的 Python/MATLAB 源代码在干净无缓存环境下可一键完整运行；
- [ ] 核心图表与数据均能由脚本端到端生成，无手动拼接或造假。
- [ ] `--require-claims` 已通过非空 headline 数值主张绑定及实际填写的 `supports_claims` 引用核验；未要求无主张图件逐张填写该字段。

## 门禁二：格式合规门（2026 Rules Compliance）
- [ ] 论文第一页为独立摘要页，含题目、摘要与关键词，**原则上不超过 1 页**；
- [ ] **确认无目录页**；CUMCM profile 摘要后依次为：一、问题重述；二、问题分析；三、模型假设；四、符号说明；五、模型的建立与求解；六、模型的分析与检验；七、模型的评价；参考文献与附录使用未编号标题；
- [ ] 已解析 `problem_source` 与 `submission_profile`：来源只描述题目来源，投稿 profile 决定语言、版式、页数和审计；无明确要求且执行 CUMCM 交付时默认 `CUMCM`，`MCM_NATIVE` 完全按题面/官方原生要求；
- [ ] 最终渲染 PDF 已按题面/赛区定义核对摘要、官方正文、附录和总页数；CUMCM 内部页数经验仅作诊断，不由简报手填事实，不以水字数、重复图或缩小字体达标；
- [ ] 论文电子版为单独的 PDF 或 Word 文件（官方建议 PDF），文件体积 $\le 20$ MB；Word 源文件另保留原生 DOCX 并完成结构检查，最终内容审计以渲染 PDF 为主；
- [ ] 如提交支撑材料，压缩包格式为 .zip 或 .rar，文件体积 $\le 20$ MB；若不提交，已在附录中明确注明。
- [ ] 如提交支撑材料，至少包含全部程序、自主查阅数据（赛题原始数据除外）和大篇幅中间图表等材料，并与附录文件列表一致。
- [ ] `appendix_sources` 已盘点正式入口直接/间接调用的辅助模块、配置生成、绘图和压力测试程序；G3 前已人工清点源码依赖，未把机器门禁误当作“无未声明依赖”证明。
- [ ] 简报通过 playbook 定义的 Schema 4 逐任务契约：`check_project_brief.py --require-profile-contract --require-schema 4 --require-gate G3`；每个任务均能定位到实际结果与论文段落，契约字段和机器约束以 playbook/checker 为准，运行结果和引用回到单一事实源；
- [ ] 论文通过 `check_paper.py --profile cumcm --award-style-audit` 的功能覆盖、表现和官方硬项审计；题面有 N 个显式问题时已传入 `--expected-questions N`，并人工核对摘要、任务要求、正文语义任务区间和附录代码映射。七章是默认脚手架；只有明确要求精确七章时才改用 `--strict-structure`。功能/闭环词汇只供定位，不应为通过审计补关键词。
- [ ] 每个有数据/模型/结果的任务已按主张和数据结构规划必要的任务特异图/表证据（覆盖输入诊断、结果/对照/验证中实际需要的功能），且正文按“先提问/引用—图表—具体读取—结论与边界”解读；纯解析任务已用推导/边界表替代并写明理由；公式一式一行，多条约束左大括号分行，关键式有编号/交叉引用，不以固定图表或公式数量作为 KPI。
- [ ] 图型由主张和数据结构选择：有序连续/轨迹才用折线；变量关系、分布、类别、矩阵、空间/场、优化和不确定性已检查是否需要散点/残差、箱线/ECDF、点图/区间、带标签热图、等高线/真实量 3D、收敛/Pareto/可行域或区间图；若全篇主要使用折线，已完成视觉缺口审计并记录理由。
- [ ] 物理机理图真实标注当前题坐标、边界和变量；流程/系统/算法图标注输入输出、接口、分支和终止；热图有行列标签、色标、单位及缺失/掩膜说明；所有图表均有正文引入、具体读取和结论/边界解释。
- [ ] 最终 PDF 渲染后人工检查无标题孤行、图表/公式裁切、图题分离、代码截断和参考文献溢出；机器结构门不能替代视觉复核。

## 门禁三：绝对匿名性门（Anonymity Check）
- [ ] 论文正文、摘要页、图表标题、图例、代码注释中无任何学校名称；
- [ ] 无参赛队员姓名、无指导教师姓名；
- [ ] 支撑材料文件夹名、文件名、压缩包名无任何参赛身份信息。

## 门禁四：AI 与学术诚信门（AI Compliance & Integrity）
- [ ] 论文在参考文献之前包含独立的《AI 工具使用声明》，未使用与已使用两种情形如实二选一；
- [ ] 如使用 AI，支撑材料中包含 `AI工具使用详情.pdf`；未使用 AI 时不虚构详情文件；
- [ ] 官方最低 AI 项目与题面/赛区附加项目已区分；若题面要求百分比、版本、页码、起始行或附录一，均已逐项填写；
- [ ] AI 详情记录了产物位置、论文页码、文件名、起始行/段落、使用范围、目的和人工核验方式；
- [ ] 外部数据记录真实标题、稳定 URL、访问日期和用途，而非笼统写“官方文件库”；
- [ ] 所有公开文献、数据和代码来源均有真实、可追溯的引用；正文标注方式与文后格式按当届官方/赛区要求核对。本清单默认采用 [序号] 与 GB/T 7714，未将其视为全国统一硬门。

## 门禁联动命令

```bash
python3 cumcm-modeling/scripts/check_reproducibility.py \
  PROJECT_ROOT/results/reproducibility.json --project-root PROJECT_ROOT \
  --require-outputs --require-claims --require-paper-artifacts --require-appendix-sources
python3 cumcm-modeling/scripts/check_figures.py \
  PROJECT_ROOT/results/reproducibility.json --project-root PROJECT_ROOT
python3 cumcm-modeling/scripts/check_project_brief.py PROJECT_ROOT/modeling-brief.md \
  --require-profile-contract --require-schema 4 --require-gate G3
python3 cumcm-modeling/scripts/check_paper.py PROJECT_ROOT/paper/final.pdf \
  --profile cumcm --award-style-audit
```

只有题面显式编号时，在命令中追加 `--expected-questions Q`；无显式编号则省略。正文页数按 playbook 的推荐/警告/失败分级，默认不传正文最小页数参数；若题面或赛区另有更严格要求，取更严格者并记录来源。正式终检不得使用 `--allow-placeholders`；2×2 仅在同一比较问题、轴/尺度对齐且最终版心可读时采用，否则拆图或删减。
