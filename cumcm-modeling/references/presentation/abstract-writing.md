# CUMCM 摘要写作指南

本指南根据用户提供的近年 CUMCM 摘要样本归纳可迁移的共同写作行为。样本只能说明一些可迁移的表达倾向，不构成固定模板、评分承诺或官方规则；当前届的页数、关键词和其他提交要求应回到 [`../core/competition-rules.md`](../core/competition-rules.md) 核验。

## 跨样本写作默认

跨样本观察支持以下归一化的 L1/跨样本写作默认，但不构成官方规则：有显式 Q 道问题时，摘要由 Q 个逐问段加 1 或 2 个共同段组成，通常满足 Q+1 ≤ P ≤ Q+2，优先 Q+1；逐问段使用“针对问题 x，”作为归一化锚点。

对有显式 Q 道问题的摘要，默认可见结构为 Q 个逐问段 + 1 或 2 个共同段，通常满足 Q+1 ≤ P ≤ Q+2，优先 Q+1。只有确有共享预处理/模型框架，或跨问题综合能提供独立信息价值时，才使用 Q+2；不能为凑数量制造空的总结段。每个逐问段以对应锚点开头，如“针对问题一，……”或“针对问题二，……”。阿拉伯数字只在与题面自身可见编号一致时使用；只固定锚点，不固定后续句法、段长、结果数量或验证内容。

若题面没有显式问题划分，关闭 Q/P 和锚点规则，按实际任务逻辑组织摘要，绝不臆造问题编号。后问可以真实继承前问的模型、参数或结果，但应明确点名所继承的对象，而不是重复或假装独立。

## 信息组织

可在开头用很短的总体段交代研究对象、背景、数据/机理基础和总体目标；随后按题面问题分别成段。每一问通常按“任务 → 数学表示/模型 → 求解或校准 → 决定性结果”自然展开，结果是中心；不具信息增量的环节压缩处理。每问都应有可定位的对象、方法和答案；若后问确实继承前问的模型或量，明确点名所继承的对象，避免重复或假装彼此独立。只有在能改变读者对结果的信心时，才加入一项验证、对照或适用边界；结尾用紧凑关键词收束。显式 Q 时，至少保留一个有信息的共同段以实现 Q+1 默认；共同段不必是固定的开头背景段，也可承担真实共享框架或综合，不能用空段凑数。无显式问题时按实际任务逻辑灵活组织。

摘要应围绕可核对的结果组织：先识别任务，再给出足以解释结果的模型/表示和求解或校准方法，随后给出直接决定性结果；不具信息增量的环节压缩处理。写出模型名称，并把求解算法单独说明；算法不是模型，软件名也不是数学方法。每问尽量给带单位、有效精度与源数据一致的直接数值，或在无法诚实量化时给出结构性结论及其条件。写出关键机制即可，不重复完整推导、过程日志和通用算法科普。

## 应避免的写法

- 不把计算精度、显示位数或不确定信息包装成过度精确的结论，也不编造数字或单位。
- 不把多个算法名堆成“方法创新”，不以文件名、内部流程、附件名或检查器术语替代模型和答案。
- 不用“效果优越、精度很高、充分证明”等自我评价代替证据；结论强度与验证范围一致。
- 不让每一问都套相同句式、相同信息顺序或相同验证配置；也不因追求对称而给本不需要的题目强行添加验证。
- 不把摘要写成工作流清单。题面没有可靠数值时，宁可报告关系、排序、可行性、趋势、边界或条件，也不填入假数字。

## 起草与自审

先为每一问从已冻结的事实和运行输出整理一份短证据草稿：要回答的目标、数学表示/模型、求解或校准动作、直接结果，以及可选的决定性证据或边界。再将这些信息改写为连贯段落，不把草稿字段变成固定小标题或机械的“四/五项公式”。完成后逐问检查：对象、方法和答案是否可定位；继承的模型或量是否被明确点名；模型与算法是否区分；数字/单位/精度是否有来源；结论是否超出验证域；是否删去了内部治理语言和不必要的算法堆叠；最后检查总体段与关键词是否真正增加信息，而非占用篇幅。
