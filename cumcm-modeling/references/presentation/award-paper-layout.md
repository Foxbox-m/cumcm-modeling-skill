# CUMCM 论文排版与版式参考

本文件只补充版式实现和渲染质检。论文内容、Schema 4、任务闭环、公式叙事、图表叙事和 G2→G3 以 [`cumcm-paper-playbook.md`](cumcm-paper-playbook.md) 为唯一主来源；本文件不把样本习惯升级为规则。

## 1. 证据与 profile 边界

严格 A1 样本的 19/19 单栏，以及指定 A1R 展示样本的 15/15 单栏，只能作为有界本地观察；单栏是 CUMCM 的强经验默认，不是官网规定。A1Q/A1R 用于呈现层校准，不能证明奖级、官方硬项或当前赛区要求；A1R 单队奖级未逐项核验，绝不称为近年国一。CUMCM profile 可把单栏作为 Skill 内部建议，`MCM_NATIVE` 和 `research_report` 完全按其真实交付要求处理。

最终先建立题面/赛区约束表，再与当届官方要求合并；A4、摘要页、目录禁令、正文上限、匿名、文件和附录等硬项以真实来源为准。字体、字号、行距、三线表、配色和页码是中性实现建议。

## 2. 页面与字体建议

- 若当届要求未另行规定，使用 A4 和四边至少 2.5 cm；提交时核对官方/赛区更严格值。
- 中文可优先 SimSun/SimHei，缺失时回退 FandolSong/FandolHei；拉丁字母和数字可优先 Times New Roman，缺失时回退 TeX Gyre Termes。
- 正文以小四/12pt、统一行距和首行 2em 为起点；标题层级稳定、公式清晰、字体可嵌入比照搬样本字号更重要。
- 在 CUMCM 默认答卷式排版中，表题置于表上、图题置于图下，正文先文后图；这些是条件经验默认，题面/用户模板或可读性需要时可调整。数值表写明物理量和单位，数值列右对齐或按小数点对齐。三线表可作为简洁默认，不把线宽设成硬指标。
- 公式独立成行，变量斜体、向量/矩阵粗体、单位正体；多条约束或联立关系逐行排布，避免把互不独立的式子挤在一行。

## 3. 页数与分账

最终渲染 PDF 记录并核对摘要、官方正文、附录和总页数；官方正文定义按当届规则，CUMCM 内部建议仅用于质量诊断：

| CUMCM 内部正文页数 | 处理 |
|---:|---|
| 26–29 | 推荐；维持证据密度，不为填满扩写 |
| 30 | 警告；核对官方正文定义并删减重复内容 |
| 24–25 | 警告；检查模型、结果、验证或任务输出是否缺失 |
| 20–23 | 强提醒；检查模型、结果、验证或任务输出是否缺失 |
| <20 | 严重质量风险；G3 简报记录证据缺口、真实原因和决定 |
| >30 | 官方失败；回到源文件修正后重跑 |

摘要原则上一页；内部建议不能覆盖题面、赛区或官方更严格要求。页数以实际渲染 PDF 和审计为准，不以水字数、重复图或缩小字体达标。

## 4. 结构门与渲染终检

最终 PDF 机器检查（推荐使用经验性版式审计参数）：

```bash
python3 <SKILL_ROOT>/scripts/check_paper.py <PROJECT_ROOT>/paper/final.pdf \
  --profile cumcm --award-style-audit
```

只有题面显式编号时追加 `--expected-questions Q`。推荐的 `--award-style-audit` 检查功能覆盖、表现和官方硬项，不固定正文一级章数；只有用户、题面或模板明确要求精确七章时才使用 `--strict-structure`，把 1.1/1.2、2.1—2.N、5.1—5.N、7.1/7.2、符号表头和未编号参考文献/附录作为内部模板门。两种模式都保留内部术语隔离、代码、附录和页面流检查。闭环词汇只供人工定位，不应为通过审计而补关键词。

最终渲染后逐页检查：无目录、摘要页完整、正文页数分账正确、标题不孤行、图表/公式不裁切、图题不与图分离、参考文献和附录不溢出、代码行不截断、页码和匿名一致。提交 DOCX 时同时检查原生 DOCX，但内容和版面审计必须查看渲染结果。

### 4.1 Page-Flow/Whitespace Pass

将最终 PDF 全页渲染，制作约每 6 页一张的彩色/灰度联系表，定位内容区间并集覆盖率偏低、最大内部连续空白偏高、图表单独占页、同页只有图+表而无叙事、标题孤行、图题分离和章节过渡异常的候选页；对候选页按原尺寸复核，并逐图执行 Figure-Text Pass。内容区间并集覆盖率低于约 60%或最大内部连续空白高于约 25%，仅是经验定位信号，不是官方规则或阻断条件；图表主导且正文叙事稀少即使覆盖率高也要检查。普通正文页默认图文共享；必要整页图/表仅在最终可读性确实要求且拆分/调整会损害信息时保留，并记录理由；参考文献短页、章节自然结束也可有合理留白。修复后必须重新渲染。

Page Composition 结果契约：候选页的判断同时看图表必要性、叙事邻接和阅读顺序，不以覆盖率单项放行；普通正文页应能在同页读到图表与提出问题、读取证据、机制解释、过渡或直接回答中的至少一个。

LaTeX 默认优先 `[htbp]`；`[H]` 仅在浮动会破坏首次依赖、且最终渲染已确认没有大面积留白时使用。题间可用 `FloatBarrier`，但不能每图滥用。图片宽度按纵横比、图内文字、信息密度和与正文共享页面的需要自适应，不统一固定宽度；窄幅、半版和版心宽度只能作为初始试排档位。

留白修复顺序：删除不必要强制分页/空段→放宽 figure/table 浮动→移动 figure/table 环境并调整相邻解释与阅读顺序→在最终可读性下限内调整尺寸/纵横比→拆合图表；长表在题面允许时正文保留代表行、完整表移支撑/附录→最后局部微调。禁止缩小正文/页边距、负 `vspace`、重复或空话补页。验收须回到最终 PDF，确认图表必要性、叙事邻接、顺序、尺寸/纵横比、浮动和图文可读性。

### 4.2 图片尺寸决策（仅供首次试排）

| 信息结构 | 初始试排宽度 | 调整依据 |
|---|---:|---|
| 简单单轴/简单机制 | 0.62–0.78 版心宽 | 图内文字、标注密度和正文是否需要共享页面 |
| 信息较密/双面板 | 0.82–1.00 版心宽 | 面板轴、图例和单位在最终尺寸下仍须可读 |
| 多面板 | 先按信息量试排；文字过小时改纵向堆叠或拆图 | 面板之间是否回答同一比较问题，不能为凑版式缩小 |

上述宽度档位仅供首次试排，不是硬门；最终可读性优先。图片应保持纵横比，禁止同时强设 `width` 与 `height` 造成拉伸；需要时使用 `keepaspectratio`，或回到图源调整纵横比。

Page Composition 结果契约：尺寸/纵横比调整后，普通正文页仍应让图或表与相邻叙事单元共享页面；若最终可读性要求整页图/表，须记录必要性及拆分/调整为何会损害信息。图表缩放的下限是最终 PDF 中的文字、刻度、图例、单位和题注可读，不以占满版心为目标。

## 5. 图表落版

图型由主张和数据结构决定；折线只用于有序连续数据或轨迹。物理机理图标注当前题坐标、边界和变量；流程/系统/算法图标注输入、输出、接口、分支和终止；热图标注行列、色标、单位和缺失/掩膜。运行生成图的事实源是脚本、输入和参数，PDF/PNG/灰度预览是同次确定性派生；非运行图用 `paper_visuals` 登记且不承载数值结果。正文按“提出问题/引用 → 图表 → 读取具体证据 → 结论与边界”解读。

正文主图优先保留 PDF/SVG 矢量容器，并按约定输出不少于 300 dpi 的 PNG/TIFF 预览和灰度 QA；热图含栅格时不能宣称纯矢量。先运行 `check_figures.py`，再按最终插入宽度人工复核。2×2 只在四个面板回答同一比较问题、轴/尺度可对齐且版心文字可读时采用。

### 5.1 论证驱动的页面组织

版面服务于论证链：定义、机制图和首次依赖的公式尽量邻近；图表与正文首次解读邻近，让读者不必跨页寻找单位、图例或结论。Page Composition 结果契约是：普通正文页的图或表应与至少一个提出问题、读取证据、机制解释、过渡或直接回答单元同页；同页只有图+表而无叙事也属于候选。必要整页视觉须写下为何最终可读性要求整页、为何拆分/调整会损害信息。标题层级用于标记真实论证动作，避免连续的空泛微标题。表与图承担不同的信息任务，不重复展示同一结论。留白和分页优先保证公式、图表、题注及其阅读顺序清晰，不以塞满版面为目标。正式 CUMCM 风格保持克制，不引入装饰性彩色块或通用商业文档风格。

## 6. Schema 4 简报检查

完整整题、最终论文或完整结果包在开始、恢复和 G1/G2/G3 前检查简报：

```bash
python3 <SKILL_ROOT>/scripts/check_project_brief.py <PROJECT_ROOT>/modeling-brief.md \
  --require-profile-contract --require-schema 4 --require-gate G3
```

按 Schema 4 逐任务契约核对每个任务能否定位到实际结果与论文段落；契约的具体字段和机器约束以 `cumcm-paper-playbook.md` 与 `check_project_brief.py` 为准。运行结果和引用回到单一事实源；页数不足时回到渲染 PDF、证据密度和任务缺口审计，不能以版式建议替代缺失证据。

## 7. 渲染后分账与职责提示

最终 PDF 审计同时输出核心论证页（问题重述起至 AI 声明、参考文献或附录中最早者之前）、主体稿、附录和总页数；strict 七章模式列出七章模板跨度，普通 award-style 模式列出可识别语义章节/功能覆盖定位。所有页数信号均为软提示；官方/题面硬上限仍按当届来源单独核对。符号说明混入独立公式、推导、坐标或索引定义，或模型假设混入软件和实现设置，只产生 `QUALITY_WARN`。

精确七章 strict 模式以 `5.1`—`5.N` 标题区间为准；普通功能模式按语义问题标题区间定位，无法可靠分块时转人工检查。正文反复出现的“问题一”等叙述不计为独立问题。章节和图件应遵循“认知瓶颈 → 渲染图件 → 正文消费”；只登记但未消费的 native schematic 仅在严格 paper-artifacts 检查中阻断。
