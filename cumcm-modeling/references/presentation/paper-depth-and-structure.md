# 论文深度诊断参考

本文件只用于诊断“当前证据是否足以支撑当前篇幅和结论”。论文执行、Schema 4 任务契约、页数诊断、作者风险检查、公式三明治、图表叙事和 G2→G3 均以 [`cumcm-paper-playbook.md`](cumcm-paper-playbook.md) 为准；本文件不复制另一套规则。

本文件各项 `Pass`/`Test` 是一次阅读中的检查维度，不表示重复全文扫描。应合并为一份问题清单，完成一次局部修复，再按受影响维度复验；若文字长度或章节结构改变，进入 G3 后重新渲染并复查页面流。

## 1. 诊断入口

先检查题面任务—论文结构映射、`submission_profile`、`summary_pages / official_body_pages / appendix_pages / total_pages` 分账和每项任务的证据路径。CUMCM、`MCM_NATIVE`、`research_report` 的边界按 playbook 解析；题面、赛区和当届规则优先于任何样本观察。

再对每个任务追问：

- 读者能否找到题面要求的输出和输入来源？
- 选择的模型是否由变量、约束、数据/机理和（适用时的）可辨识性支持？是否有同口径基线或明确不适用理由？
- 求解设置、参数、单位、离散/步长/收敛依据是否能复现？
- 结果是否是正式运行输出，且有解释、局部验证和结论边界？
- 图表、公式和附录是否承担可定位的证据功能？

这些问题用于检查 Functional Coverage Contract 是否有真实证据，不把一级章数量误当成数学深度。默认七章稿和合并/拆分后的其他结构使用同一功能标准。若问题的答案只是“模型更复杂”“结果较好”或“如图所示”，说明深度不足，应回到模型、运行或正文证据，而不是扩写套话。

若正文使用了 Layer B，还要诊断是否出现 Pattern 叙事泄漏或反向塑模：叙事和图件应解释已经冻结且有证据的当前题结构，不能用卡片语言替代对象、关系、现象与验证，也不能反过来决定模型选择；发现泄漏时回到对应模型与论证证据修复。

## 国奖答卷感与分问映射审查

“答卷感”不是复制某篇论文的句式，而是让阅卷者沿题面动作快速核对证据。审查主模型时至少追问七项：

1. 是否先明确题面任务、输出口径和本问与前后问的接口？
2. 是否说明关键结构困难，以及适用时为什么简单参照不足？
3. 关键关系、参数和约束是否有题面、数据、机理假设或可核验来源？
4. 数学表达是否足以让读者复现，而非只写模型名称、软件或求解器？
5. 主要结果是否有变量/约束/机制解释，而不只报告一个最优值或拟合指标？
6. 是否有与风险对应的局部验证、基线、敏感性、误差或边界？
7. 是否在本问末尾直接回答题面，并说明结论可推广到哪里、不能推广到哪里？

对有显式编号的题面，逐问建立“题面任务 → 问题分析 → 模型与求解 → 结果 → 局部验证 → 直接答案”的功能映射；使用默认七章模板时对应 `2.N` 与 `5.N`，其他结构按语义任务区间定位。题面没有显式编号时，按语义任务建立同一映射并人工核对。映射审查不能用章节数量替代，也不能因为模型或图表存在就视为任务已回答。

## 2. 证据密度诊断

高密度意味着单位版面同时承担动机、输入、推导、参数、结果、验证和机制解释。诊断时优先删除背景复述、空泛评价、重复图和不产生新证据的公共章；把省下的空间用于关键假设、适用时的可辨识性、误差、约束、对照和适用边界。

摘要只保留对象、任务方法、正式量化结果、可信度和边界；正文应让模型、结果和局部验证成为主体。页数落在 playbook 的推荐/警告区间时，先判断证据是否缺失，不以字数或图表数量达标；20–23 页是强提醒，少于 20 页是严重质量风险，页数信号不是审批结论。

### Phenomenon Explanation Pass

这是人工机会检查，不是 Gate：对每个主要结果追问它对应的题目现象或状态、主导关系/变量/约束/几何/机理是什么、基线为何不同，以及解释是否确实来自现有模型。若只能写“效果更好”或“如图所示”，回到结果与模型补足解释，而不是增加套话。

### Analytical Elevation Opportunity

这是人工机会检查，不是 Gate：仅当守恒、单调、对称、尺度、界或临界条件能由现有模型严格推导，且性质化表达能带来解释或简化价值时，才提升为性质/命题；否则保留为数值观察，不造定理，也不强制 theorem 环境。

## 3. 按题型诊断缺口

| 题型 | 首要检查 | 常见深度缺口 |
|---|---|---|
| 优化、配置、调度、路径 | 基线、可行域、活跃约束、目标权衡、收敛/稳定性 | 只写求解器或启发式，没有约束解释和同口径对照 |
| 预测、统计、机器学习 | 数据诊断、泄漏、切分、样本外误差、不确定性 | 只报告拟合指标，没有处理影响、基线或外推边界 |
| 机理、微分方程、仿真 | 状态、单位、边界、初值、适用时的参数辨识、离散和守恒 | 只展示曲线，缺少物理方向、步长/网格和参数来源 |
| 评价、决策、建议 | 指标定义、权衡、敏感性和可执行接口 | 权重或排序没有依据，建议不能回到结果和约束 |
| 纯解析 | 推导链、条件、边界和情形覆盖 | 硬塞数据图或把未证明的直觉写成结论 |

诊断结论必须指向一个可修复的证据位置或明确的适用边界。不要因某类论文常用某模型、某图型或某页数而推断当前题也应照用。

### Equation Pass

在结构和文字定稿前逐式做一次 Equation Pass：对每个关键公式核对“前置关系或依据 → 公式动作 → 符号/单位/参数来源 → 如何进入求解或结论”。同时检查编号、交叉引用、边界/初值/约束和量纲（适用时），并确认公式后的解释没有把相关性写成因果、把仿真写成证明或把未辨识参数写成已知量。发现断点时回到模型或结果证据修复，不能只补一句“由此可知”。纯解析任务可用推导、边界表或情形表完成 Equation Pass。

### 章节证据预算

按功能建立证据预算，而不是固定页数预算：题目理解保留对象、动作和输出；问题分析保留结构困难、表示路线和验证出口；假设/符号只保留会改变模型或解释公式的内容；模型论证区间优先分配推导/求解、正式结果、局部验证和题目化解释；综合检验区间保留跨问或系统级证据；评价区间保留有证据的缺点、边界和整体改进。使用默认七章模板时，上述功能分别映射到问题重述/分析、模型假设/符号说明、第五章、第六章和第七章；其他结构按语义区间完成同样预算。删减或扩展均以证据闭环为依据，不以每章平均页数、字数、图表数或公式数达标。

## Argument / Visual pass

### Definition Dependency Pass

逐项核对每个新坐标、状态、约束和非平凡关系，确认它们都在首次依赖的公式或推导之前完成定义；若有缺口，应把定义或机制图前移到首次依赖之前。该检查用于修复阅读顺序和视觉债务，不把所有前向引用变硬门，也不以形式顺序替代数学语义判断。

### Section Responsibility Pass

使用默认七章模板时逐章核对可见职责：符号章仅放符号表，假设章仅放全局建模假设，第五章承担建模论证，第六章承担跨问题的新检验。非七章稿按“必要假设与符号—模型论证—逐问验证—跨问检验”的语义区间核对。机器只对可见污染发 `QUALITY_WARN`，不把章节职责词法提示升级为硬失败，也不以章节名称推断数学质量。

### Paper Voice Pass

逐段检查是否把代码架构、数据治理、运行入口、Schema/Gate/QA、调用关系或重复的全篇组织说明写进前台论文；发现后先用删除测试和换语言测试定位，再移到内部/支撑材料或改写为实际数学含义。同时保护题面事实、数学对象、推导、求解原则、正式结果、机制解释、必要验证、结论边界与答案定位，不因追求口语自然删掉证据闭环。第六章若只是在回顾“全文如何组织”，而没有新增跨问风险证据，也应回到章节职责修复。

### Question Asymmetry Pass

逐问比较摘要和各语义任务区间的标题、篇幅层级、句法和收束方式；使用默认七章模板时重点比较 `2.N` 与 `5.N`。检查是否机械复制相同四件套、固定段长、统一验证数量或反复使用“直接回答：”标签。不同问题允许不对称，但每一问的题面映射、量化或结构性结论、必要验证和直接答案仍须可定位；不能以打散句式为由破坏闭环。

在人工复核中增加两项不设机器门的检查：

- **Chain Break Test**：从“答案”反向追到“正式结果 ← 模型输出 ← 目标/判定 ← 关系 ← 题面事实/假设”。任一箭头没有可定位的文字、公式、数据或验证，记录断点并回到相应证据位置修复。
- **Visual Debt Test**：逐页检查定义、首次依赖的公式、机制图、图表及其首次解读是否相邻且可读；若读者需跨页寻找前提、图例、单位或结论，记录为视觉债务，优先通过版面或图表重排修复。

Paper Voice Pass、Question Asymmetry Pass、Chain Break Test 与 Visual Debt Test 都属于人工 Argument/Visual pass，不新增硬 Gate 或 KPI；七章骨架通过也不能替代它们。机器对少量明确复合短语的软提示只用于定位，不能代替上述人工判断。

局部语态或限定语修改不自动触发语义强调；仅在当前任务出现具体导航缺口，或最终正式交付确需扫读导航时，才启用相应强调检查。

## 4. 深度放行

深度诊断通过的最低条件是：每个题面任务都有可追溯输出；每个主要模型或高影响结论都有合适参照（继承任务可复用上游参照，纯解析任务可用解析特例、极限、守恒、量纲或边界）或明确不适用理由，并在适用时同口径比较；关键假设和参数有边界证据；主要风险有局部验证；图表和公式能解释而非装饰；论文结论没有超出数据、模型和实验设计支持的范围。

诊断不能替代实际运行、渲染 PDF/DOCX、引用核验或 G3 人工审查。发现缺口后按 playbook 回到 G1、G2 或 G3 修复，并重新检查同一证据链。

## 5. 写作边界回归

精确七章 strict 模式只把 `5.1`—`5.N` 标题区间作为逐问闭环边界；普通功能模式按“问题一/第一问”等语义标题区间定位，无法可靠分块时进入人工检查。“问题一”等偶然叙述、摘要或问题重述中的标签不是新问题。多问先人工判断 Cascade/Parallel/Hybrid：只有真实级联才展开继承关系、前问不足和本问新增；并列任务直接写独立对象、数据/场景、困难、表示和验证出口；混合任务只写真实共享核心与接口。共享核心仅在同时服务至少两问、可被后续直接调用、前置可减少重复且不含单问细节时前置。

章节职责与附录内容采用保守提示：符号说明中的独立公式/推导/坐标或索引定义、模型假设中的软件/数值实现设置只产生 `QUALITY_WARN`。附录题号到入口仍须硬映射，但若逐问题块只有文件映射，未看见 `def/function/class/import` 或控制/函数签名等本问特异核心证据，仅提示人工复核，不作语义评分。认知瓶颈应先落实为图件，再在正文紧邻消费；`paper_visuals` 反向消费检查只在严格 paper-artifacts 模式生效。
