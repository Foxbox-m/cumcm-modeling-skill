# G2-H 数据与结果人工审查

本文件定义 G2 内的数据与结果人工子门。G2-H 不是 G4，不改变 Schema、`reproducibility.json` 或既有 G1-H/G2-A 结构；它只确认已经完成的计算、优化与验证是否可以冻结为 G3 大纲事实。

## 1. 触发与前置

以下情形触发 G2-H：完整 CUMCM 整题、完整大纲、完整结果包、真实跨问题依赖的任务，或用户明确要求“先审查结果再综合大纲”。局部任务可在项目记录中说明范围并省略；省略不是批准。

只有正式计算、与主导风险匹配的验证，以及 G2-A 机器检查已经实际运行后，才可提交 G2-H。机器成功、文件存在或人工沉默都不能代替明确决定。

## 2. 报告与决定

报告写入 `PROJECT_ROOT/G2-H_data_review.md`，顶部状态头必须为：

```yaml
---
review_schema_version: 1
gate: G2-H
decision: PENDING
---
```

`decision` 只允许 `PENDING`、`APPROVED`、`REVISE`、`ROLLBACK`。`APPROVED` 后才允许冻结数据/预处理、最终模型、算法、核心结果和验证事实，并进入 G3 详细大纲综合。`REVISE` 回到计算或验证；`ROLLBACK` 回到模型选择、G1 或 G1-H。任何其他状态均无效。

## 3. 自适应报告内容

报告按实际风险展开，不复制运行日志或 G1/G2-A 的完整记录；至少提供以下可核对区段：

```markdown
# G2-H 数据与结果人工审查报告

## 数据与预处理
来源、筛选、缺失/异常处理、单位/坐标变换，以及会改变事实含义的处理。

## 最终模型与算法
实际采用的模型、参数、求解/训练算法和输入输出边界；仅记录已运行版本。若存在 baseline 或 challenger，核对其同口径比较及采用理由；没有时不虚构比较或配额。

## 核心结果
进入 G3 的关键数值、结构化结果与必要 `figure_data` 及其项目内事实源。

## 验证与稳健性
已经完成的约束、误差、边界、收敛、敏感性、样本外或其他相关验证及发现；只展开当前任务真正触发的风险。

- 若存在显式优化、分组、调度或结构搜索，核对开放决策变量是否对正式目标/可行性具有实际区分度。若不同方案目标相同或差异仅在数值误差内、出现大面积等价解/平坦目标，或最优解持续贴在人为分段点、搜索边界、离散网格边界，则记录为优化退化/边界锁定；不得把任意 tie-breaking、极窄分组或等价方案解释为优化收益。优先简化自由度、报告等价解或修正目标/约束，不通过增加求解器掩盖退化。出现退化后还要区分其来源：

  - **data-supported simple result**：使用至少一个不共享当前表示偏差的轻量探针后，结果仍保持简单/等价/边界结构；
  - **representation/objective-induced degeneracy**：替代表示、原变量动作或目标充分性检查显示当前结果主要由参数化、人工边界、目标单调性或偏好压缩造成。

  前者可以冻结并作为正式负结果；后者不得冻结为最终事实，应 `REVISE` 或 `ROLLBACK` 到最早受影响的模型选择/数学定式阶段。不得因为结果不够丰富而把 data-supported simple result 判为失败。
- 若存在监督学习、统计预测、重复测量或层级数据，核对验证切分单位与真实独立采样单位/时间信息集一致；同一对象、批次或未来信息不得跨训练与验证。标准化、插补、校正、特征选择、降维、阈值与超参数等数据依赖步骤须在训练折内拟合，再应用于验证折；headline 指标必须来自该无泄漏协议。
- 若依据验证/回测结果选择过模型或策略，按 `validation-and-sensitivity.md` 核对完整选择过程与最终评估分离，不能仅凭上游预测无泄漏就认定下游策略已独立验证。
- 若预测/估计结果会进入下游决策，核对最终模型选择是否同时使用了 G1 预声明的 task-level 证据。平均预测指标与决策指标发生冲突时，应说明取舍依据；不得在 G2 结果出来后临时创建有利子群、阈值或评价指标来挽救候选模型。
- **Realized cross-question propagation**：对 G1 声明存在真实依赖的每条边，核对上游输出是否真的被下游计算消费。至少能定位“上游对象/参数/预测分布/不确定性 → 下游方程或代码输入 → 下游结果”的实际路径。若下游重新拟合的是同一结构，只要接口定义保持一致，可记为 `shared structure + re-estimation`；若实际代码更换了 representation、核心关系或随机/观测语义，却没有 G1 批准的 `core-replacement` 证据，则判 `REVISE/ROLLBACK`。声称传播但实际未进入下游结果的参数、误差或状态不得仅靠文字保留。
- 若上游模型、参数、预处理或输入发生变化，按 `reproducibility.md` 的“上游变更与依赖重算”核验或重算受影响结果，并核对当前结果、验证记录和事实源；不能只凭文字宣称变化已经传播。
- 若导出方案的舍入、取整、聚合、单位换算或编号映射可能改变含义或可行性，按 `../models/optimization-models.md` 的“实际交付数值回验”检查交付文件中的目标和硬约束。

## G1→G2 偏差
记录相对已批准方案的实际改动、原因和影响；无偏差则明确写无。

## 重大风险
尚未关闭的事实、处理、模型、算法、结果或验证风险及其影响范围。

## 建议进入大纲的核心事实
列出已核对、可追溯且足以支撑大纲主张的核心事实：
- canonical result（主导结果与数值）；
- 关键模型关系与推导主线；
- 优化改进证据（相对 baseline 的提升与停搜依据）；
- G1→G2 方案修改与原因；
- 尚未关闭的边界与风险。

## 人工清单与意见
- [ ] 数据和预处理语义可解释
- [ ] 最终模型/算法与实际运行一致
- [ ] 核心结果、单位和结构化数据资产来源可追溯
- [ ] 验证已运行且能覆盖主要风险
- [ ] 若任务触发显式优化或统计/ML验证，已排查优化退化/边界锁定与切分/预处理泄漏；不适用时无需机械检查。
- [ ] G1→G2 偏差已说明
- [ ] 核心事实不超出证据

review_comment:
<人工意见>
```

## 4. 通过与禁止事项

`APPROVED` 只表示人工明确同意按报告冻结并进入 G3 详细大纲综合；它不替代 G2-A、G3 或数学判断。`REVISE` 和 `ROLLBACK` 必须重做受影响阶段并重新生成报告。不得自动批准、不打分、编造结果、抄写完整日志、重复 G1/G2-A 工作，或把 G2-H 变成新的复现/Schema 结构。保持 `PENDING` 时不得开始 G3 大纲综合。
