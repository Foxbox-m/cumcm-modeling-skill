# G1-H 人工建模审查

本文件定义 G1 内部唯一的人工建模子门。它回答的是“方向是否符合题意、方案是否值得正式计算”，不替代 G1 的建模证据、G2 的计算证据或 G3 的详细大纲综合。G1-H 不新增顶层 Gate，不修改 Schema 4 或 `reproducibility.json`。

## 1. 何时触发

完整 CUMCM 整题、用户要求建立并求解完整模型、完整建模任务/完整大纲/完整结果包、含有真实跨问依赖的多任务，或预计会投入明显编码、训练、优化、仿真成本的任务，均在正式主模型实现前触发 G1-H。用户明确要求“计算前先审方案”时也触发。

单纯解释模型、单项数据审计、已有模型的局部代码修复、单个公式推导、单张图、局部大纲修改，或只要候选建议且不进入正式求解的任务，可省略。若省略，应说明这是局部任务，不把省略误记为批准。

完整任务默认不能由模型自行跳过。只有用户明确说“跳过人工建模审查”“无需人工审核，直接按当前方案求解”之类的意思，才可记录为 `explicit_user_skip` 并继续现有 G1；自动检查通过、模型相似历史论文、模型自评合理或用户没有回复，都不是批准。

## 2. G1-H 前的计算边界

为理解真实数据，可以进行数据读取、缺失/异常/分布/相关性和时间顺序审计、描述性统计、量纲与边界检查、小规模解析例、极端情形、极小可行性试验，以及必要的 representation、invariant 或 identifiability 初步诊断；**显式优化任务还允许为选模而运行低分辨率/代理粗搜、小规模精确解、松弛界或少量局部动作探针，用于判断表示偏差、变量交互和 improvement gap。上述结果只能作为 G1-H 的方向证据，不得作为正式最优结果或最终大纲结论。**结果只用于发现风险和选择方案，不是正式答案。

在人工明确批准（或记录用户显式跳过）前，不得正式运行主模型、对完整数据正式训练或优化、大规模参数搜索、正式仿真、生成最优方案/预测结果等正式结论、生成正式结果或最终大纲结论，或依据主结果进入正式结果综合。允许的诊断不应被包装成正式求解。

## 3. 状态头与报告职责

完成结构解析、可检验 baseline、Gap Check、必要的候选扩展、数学定式、求解路线和验证计划后，在 `PROJECT_ROOT/preliminary-modeling-report.md` 写一次面向人的报告。该报告是 G1-H 的阅读界面，不是大纲成稿，不是运行结果事实源，也不是 `modeling-brief.md` 的替代品；不复制完整审计日志或所有模型卡内容，不写正式结果数字。

报告顶部保留轻量状态头：

```yaml
---
review_schema_version: 1
gate: G1-H
decision: PENDING  # 允许值：PENDING | APPROVED | REVISE | SKIPPED_BY_USER
skip_evidence: ""
skip_recorded_at: ""
---
```

`decision` 只使用 `PENDING`、`APPROVED`、`REVISE`、`SKIPPED_BY_USER`。人工修改状态时保留审查意见和日期/身份等项目需要的记录，但不要把结果、运行状态或新的 Schema 字段塞入状态头。

## 4. 核心项与条件触发项信息契约

以下是自适应信息契约，不是固定篇幅、固定标题配额或逐问模板。报告按真实任务和风险组织，可使用自然语言、列表、表格或紧凑示例；简单题可省略不适用项，没有真实竞争关系时不虚构备选或回退。

### 核心项（每次 G1-H 都应可定位）

1. **题目要求与必需输出**：说明题目原始任务动词、交付量和关键数据/约束；输出要能直接回答题面。
2. **可检验 baseline**：给出最小数学表示、输入—处理—求解—输出路径和检查方法。baseline 可以是现状、朴素、松弛、解析特例或极限情形。
3. **Gap Check、结构充分性与升级决定**：记录题意、结构、数据或结果缺口；baseline 若遗漏 `problem-analysis` 已识别的答案敏感结构，只能作为参照，不能直接 selected。说明缺口处置（题意修正、数据/信息处置、求解/验证补强）以及是否保持 baseline、替换主机制或进行一次有证据的扩展。
4. **最终模型与算法/求解流程**：分别说明变量、关系、目标、约束和机理/统计结构，以及求解步骤。多组件路线必须能区分 primary mechanism、decision layer、solver、diagnostic 和 baseline/challenger；同一中间目标不得保留多个未决 primary mechanism。
5. **关键假设与决定性验证**：只列会改变模型或答案的假设、失效边界和与主导风险匹配的验证及判断依据。

### 条件触发项（仅在题面或风险实际触发时加入）

- **真实竞争方案**：存在能改变选择的替代解释或方案时，说明其可行依据、未选原因与切换条件；未触发时直接省略。
- **参数/状态可辨识性**：存在待估参数或隐藏状态时，说明观测能力、识别检查和不辨识后果。
- **复杂失败边界/敏感性**：非线性、随机、边界脆弱或结果不稳定时，给出必要的敏感性、极端情形或失败条件。
- **跨问接口/误差传播**：参数、状态、数据、约束或误差确实传递时，记录 `shared canonical object`、表示尺度/核心关系、随机或观测层、实际下游接口及其影响。若后问只改变合法信息口径并在同结构下重新估计参数，明确记为 `shared structure + re-estimation`；若改变表示、核心函数族、时间/空间参数化、随机结构或观测误差语义，则按 `core replacement` 审查其失效证据和同口径对照。
- **显式优化的表示/搜索风险**：仅当存在优化且可能有表示或搜索偏差时，记录原始决策变量、真正开放变量、人为固定及理由、搜索族/表示偏差、变量交互。
- **昂贵双保真**：只有使用 fast/代理与 full/formal validation 时，才说明两者口径、seed/baseline、improvement gap、无改善后的扩展动作和正式验收关系。
- **多主导风险或扩展实现风险**：分别给出多项决定性验证，或说明回退/停止路线；不因清单完整而强迫不存在的内容。

四类 Gap 可直接标注为“题意 Gap / 结构 Gap / 数据 Gap / 结果 Gap”。一个紧凑记录可以是：“题面要求……；baseline 输出……并以……检验；Gap Check 发现……，先判定属于题意修正、数据/信息处置、求解/验证补强或模型/表示扩展；只有最后一种触发时，才写新增机制、求解和验证；只写实际触发的条件项，无需逐项声明未触发项。”这只是表达示例，不是固定字段或固定问题数量。

每个任务都要显式回答：题目真正要求什么、当前模型最终输出什么、两者是否一一对应。最高优先级是题意和输出，之后才是数据支持、数学表示、算法可实现性、简化空间和复杂度收益。任务类型只帮助组织候选，不得由题号字母、往年套路或模型卡机械决定。

### 核心判断与触发式审查清单

- [ ] 题意、必需输出、数据和硬约束一一对应。
- [ ] baseline 可运行或可检验，且 Gap Check 的升级决定有证据；若 baseline 被用于性能提升、正式对照或赛时 fallback，它能够完成真实任务并给出同口径输出，否则已明确降为 diagnostic reference。
- [ ] baseline 已通过结构充分性检查；若存在答案敏感的层级、删失/观测、时序、几何/守恒、特殊数据空间、测量误差或决策约束，已建模或有证据说明可忽略。
- [ ] 多组件路线角色不重复；同一中间目标只有一个 selected primary mechanism，其余已降为 baseline/challenger/diagnostic/validation，或 ensemble 已有同口径增益与消融证据。
- [ ] 决策时信息集无未来/后验变量泄漏；重复测量、删失和观测层级已按题意处理。
- [ ] 若必需输出出现分组/等级/有限动作等离散交付，已判断该离散结构是题面/机理本身的结构，还是连续底层关系的运营压缩；不存在为了满足输出形式直接固定组数或切点的问题。
- [ ] 若使用自建效用、风险、评分、加权目标或 penalty，已做最低成本的 objective adequacy probe；不存在未经解释的单调边界锁定、大面积平坦、人工分段极值或偏好不可辨识，或已明确准备一个最小替代表示探针。
- [ ] 若后续 delta 的预测/状态会进入最终决策，模型保留判据已与最终任务接口对齐；平均预测指标不是唯一门槛，task-level 指标已在看到候选结果前由题面或主导风险声明。
- [ ] 真实跨问依赖采用 shared core + delta：上下游共享对象的 representation、core relation、stochastic/measurement semantics 已逐项核对；若发生 core replacement，已指出具体失效证据、被修改的接口轴、保持不变的接口以及 inherited-core 同口径对照。不存在仅因题号变化同时改写多个结构轴。
- [ ] 模型与算法已分开，关键假设和决定性验证与风险匹配；高成本/高失败风险候选若触发赛时预算契约，已先用最小 load-bearing risk probe 决定是否值得完整实现。
- [ ] 真实存在的竞争方案、跨问接口或回退条件已说明；未触发的条件项直接省略。
- [ ] 显式优化表示/搜索风险：审查原始决策变量、真正开放变量、人工固定及理由、表示偏差与变量交互；不把 fast/full 强加给普通显式优化。
- [ ] 昂贵双保真实际触发时，才审查 fast/full、seed/baseline、improvement gap 与无改善后的扩展动作。

报告必须区分模型和算法：模型给出数学/统计/机理表示、变量、关系、目标与约束；算法给出解析推导、数值积分、优化器、训练或采样过程。GA、PSO、MILP solver、XGBoost training procedure 等工具不能单独充当模型。

## 5. 人工决定与回退协议

`APPROVED` 表示人工明确同意按当前方案继续，例如“通过，按这个方案计算”“方案没问题，继续”“开始正式求解”。批准后先执行现有 G1，再在 G1 放行后进入正式实现与计算。`REVISE` 表示意见尚未解决；报告必须回到意见影响的最早阶段后重新生成并再次审查。未回复和自动 checker 通过均保持 `PENDING`。

| 人工发现 | 最早回退位置 |
|---|---|
| 题意或子问依赖理解错误 | 题目分析 |
| 数据能力判断错误 | 数据审计 |
| 遗漏明显候选 | 候选探索 |
| 主模型或复杂度不合理 | 模型比较/选择 |
| 目标函数、约束或数学表示错误 | 数学定式 |
| 算法不适配 | 求解设计 |
| 关键自由度过早冻结或评价/搜索失配 | 候选探索/数学定式/求解设计（取最早受影响阶段） |
| 验证不足 | G1 前验证计划 |

若跨问接口发生无证据断裂，`REVISE` 回到最早发生断裂的 `problem-analysis / model-selection`，而不是仅修改报告措辞。

只重做受影响阶段及其后续工作，再生成报告；不得用文字润色把未解决的方向问题伪装为批准。

G1-H 的有效协议只有：

```text
PENDING          → 等待人工决定，不得正式主模型计算
REVISE           → 按意见回退、重建报告、再次审查
APPROVED         → 人工批准，执行现有 G1，通过后正式实现
SKIPPED_BY_USER  → 用户显式要求跳过；必须记录用户原话与时间；不是 APPROVED，仅允许继续现有 G1
```

用户显式跳过时记录 `decision: SKIPPED_BY_USER` 以及 `skip_evidence` 和 `skip_recorded_at`（或正文中 `explicit_user_skip` 和原话/时间），仍执行现有 G1；跳过不是 `APPROVED`，也不改变 G1/G2/G3、Schema 4 或复现清单字段。模型不得自行生成跳过状态。

## 6. 禁止事项

- 人工决定只使用 `APPROVED`/`REVISE`（或用户显式要求跳过时记录 `SKIPPED_BY_USER`），不打分，不把意图匹配、创新性或模型质量换算为数值。
- 不给意图匹配、创新性或模型质量打分，不设固定候选数量、固定报告篇幅或固定问题模板。
- 不把“模型名称数量”当作深度或创新；也不设置“最多/至少 N 个模型”的机械门槛。审查对象是结构是否充分、角色是否重复、增量是否有证据。
- 不按赛题字母或题号字母套“某类题必须某模型”；依据只能是题面任务、数据结构、硬约束、必需输出和真实子问关系。
- 不把历史获奖论文相似性当人工批准，不以自动检查代替人工决定。
- 不在报告中伪造结果、固定运行状态、数据证据或尚未核实的引用。
- 不因为预计结果过于简单、后问无增益或最优方案退化，就主动提高模型复杂度、增加组数或寻找能够制造显著差异的评价指标；只有可观察的 representation/objective/metric Gap 才允许一次最小替代探针。
