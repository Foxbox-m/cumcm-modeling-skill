# CUMCM 外部文献检索与逐条核验规范

> **调用时机**：需要外部理论、事实、数据、标准、软件或算法依据时读取；参考文献定稿前再次执行。  
> **核心原则**：Skill 内置蒸馏先验是常规入口；外部优秀论文库只有在已配置且明确触发时才用于启发和定位线索，不自动成为当前论文的引用依据。任何文献条目与正文主张都必须由可访问来源核对，不能凭模型记忆补全。

## 1. 先区分“方法启发”与“论文引用”

- A1R/A1/A1Q/M1/M3 可帮助发现经典来源和失败模式；先完成当前题独立简报，再按需读取数学推导原语与相关模型卡。`method-evidence.md`/外部历史语料仅在来源追溯、历史失败案例或历史方案比较等明确触发成立且已配置外部库时加载；`cumcm-paper-priors.md` 只在已有独立模型与结果的论文写作/表现校准阶段读取。需要历史来源、方法适配/反例或精确来源页码时，才用 `search_corpus.py` 定向检索 A1R/A1/A1Q/M1，并回到相关页核对上下文。A1R 的图像转制PDF与单队奖级状态必须按 `recent_manifest.json` 的来源边界表述。
- 历史参赛论文中的参考文献只能作为二次线索。当前论文若使用某理论或算法，应尽量找到并阅读原始论文、正式教材、标准或官方文档。
- 不因某资料位于本地库中就把它写入参考文献，也不一概禁止引用竞赛论文。只有当竞赛论文本身是被讨论对象、来源公开稳定且引用目的明确时，才按真实元数据引用。
- 题目附件、公开数据、软件和网页资料按各自真实来源引用；不要为没有 DOI 的合法来源虚构 DOI。

## 2. 检索与核验顺序

1. **定义待支撑主张**：写清需要文献支持的具体句子、方法或数据事实，避免先堆文献再找用途。
2. **发现候选来源**：默认先用题面、Skill 内置蒸馏证据和已核验来源。只有外部库已配置且存在明确待支撑主张、历史失败/比较、方法适配反例或精确页码需求时，才可用下列命令定向检索；外部库只是可选证据扩展：

   ```bash
   python3 <SKILL_ROOT>/scripts/search_corpus.py 查询词 \
     --corpus-root <CORPUS_ROOT> --tag A1R,A1,A1Q,M1 --limit 5
   # 或：--metadata <METADATA>
   ```

   外部网络候选发现仍可运行 `scripts/search_literature.py 查询词 --provider crossref|semantic-scholar|both --timeout-seconds 5 --retries 0 --json`。默认使用一个 Provider，外部 API 只提供书目元数据，结果固定是 `candidate_unverified`，不自动写入 citation-ledger，也不替代正文核验。
3. **回到一手或权威页面**：对候选 DOI、出版社、期刊/会议官网、教材版权页、标准发布机构、数据提供方或软件官方文档交叉核对；发现脚本不下载全文，阅读正文/摘要只在允许范围内进行。
4. **核对书目信息**：标题、作者、年份、来源、卷期页码或文章号、版本、DOI/URL 必须彼此对应。DOI 存在时解析并核对；无 DOI 不构成失败。
5. **核对内容支持**：定位页码、章节、定理、表格或官方字段，确认来源确实支持正文主张。只读到摘要时，只能引用摘要明确支持的内容。
6. **人工记录并格式化**：只有人工完成交叉核对、阅读范围和内容支持后，才由团队写入 `citation-ledger.md` 的已核验状态，再按当届要求生成文后条目和正文编号；格式正确不能替代真实性核验。

## 3. 外部网络故障与赛时回退

`search_literature.py` 默认单 Provider、5 秒超时、零重试；网络或 SSL、403、429、5xx 失败后本轮立即停止联网，不在后续 turn 自动重复，也不把搜索失败当作主张为真或为假。回退到题面、Skill 内置蒸馏先验和已核验来源；若外部证据不可替代，将主张/引用标为待核验并限制结论。网络或外部库不可用不影响当前题的独立模型、计算和论文论证标准。只有查询发生实质变化且剩余时间允许时，才由用户或任务需要显式再试或使用 `--retries 1`。OpenAlex、Semantic Scholar、Crossref 均只是聚合/登记元数据，不能替代内容支持。

## 4. 引用证据台账

在 `PROJECT_ROOT/results/citation-ledger.md` 或等价机器可读文件中逐条记录：

| 引用键 | 正文主张/用途 | 来源类型 | 题名与作者 | 年份与载体 | DOI/稳定 URL | 内容定位 | 核验来源 | 状态 |
|---|---|---|---|---|---|---|---|---|
| cite-01 |  | 原始论文/教材/标准/数据/软件 |  |  | 无则如实留空 | 页码/章节/表格 | 出版社/登记机构/官方页 | 已核验/待核验/不采用 |

最低要求：

- 每个文后条目至少对应一个正文引用位置和一个具体用途；
- 每个关键外部主张能回到实际阅读的证据位置；
- “待核验”条目不能进入最终论文；无法核实的字段不猜测、不拼接；
- 同一来源支持多个主张时分别记录内容位置，避免超出原文范围。

## 5. 不同来源的核验重点

| 来源 | 优先核验点 |
|---|---|
| 期刊/会议论文 | 出版社或会议官网、DOI 元数据、版本与文章号；预印本和正式版不要混写 |
| 中文论文 | 期刊官网、国家级文献平台或可靠馆藏元数据；机构权限受限时明确未阅读全文 |
| 教材/专著 | 作者、书名、版次、出版社、年份、ISBN，以及实际使用页码或章节 |
| 标准/政策 | 发布机构、标准号/文号、版本、生效日期和官方页面；最终阶段复核是否仍现行 |
| 数据集/网页 | 提供机构、数据集或页面标题、版本/发布日期、稳定 URL、访问日期和字段定义 |
| 软件/开源包 | 官方文档或发行页、实际使用版本；如有推荐引用论文，核对其与所用功能的关系 |

### 标准与数值的语义一致性

外部标准中的数字必须与论文指标在语义、单位、对象和适用条件上逐项一致；不要把某标准中出现的时长、速度或阈值跨概念改写成另一指标的上限。来源只支持其明确覆盖的命题。若论文阈值是团队为决策而设且没有外部来源，应标为“建模阈值/决策阈值”，不能写成安全红线。

### 引用覆盖与正文消费

引用审查还要反向检查正文：每条保留的文献应支撑一个可定位的外部主张、方法来源或数据事实，并在正文实际被消费；只为凑数量的条目删除。图件若依赖外部资料，图题或邻近正文应说明来源和用途；本题自行绘制的 native schematic 不伪装成外部文献证据。

## 6. 高风险情形

- **模型“回忆”出完整条目**：只作为搜索关键词，未被外部来源核对前不得引用。
- **标题真实但作者、年份或 DOI 错配**：整条视为未核验，不从多个相似记录拼接。
- **只看到二手转述**：回溯原始来源；若无法取得，引用实际阅读的二手来源并限制表述。
- **数据库元数据互相冲突**：优先一手发布方；保留差异记录，无法消解时不采用或显式说明。
- **引用只为凑数量**：删除。引用数量没有固定优胜区间，以完整支撑必要主张为准。
- **外部信息可能变化**：重新联网核验最新官方来源；在无法联网时标记为待核验，不声称当前有效。

## 7. 定稿放行条件

参考文献定稿前逐条确认：书目信息真实、正文主张被来源实际支持、正文编号与文后列表一一对应、公开数据和软件得到必要归属、没有待核验条目。若当届规则规定特定格式，只在最终提交阶段加载规则层并套用；不要让格式要求反向限制早期模型探索。
