# CUMCM 开放式模型探索与证据收敛指南

> **核心原则**：模型由当前赛题的数学结构决定。往年优秀论文、专家评析和本地模型卡用于启发、反证和校准，不是模型白名单，也不限定创新或发散空间。

模型深度、基线—缺口—扩展能力审计和不应套用高阶模型的条件，统一见 [`../presentation/paper-depth-and-structure.md`](../presentation/paper-depth-and-structure.md)。本文件负责候选探索和证据比较，不重复页面契约。

---

## 1. 先发散：从问题结构生成候选

在查看历史解法前，先独立回答：

1. **目标是什么**：解释、评价、预测、识别、反演、优化、控制、仿真还是决策？
2. **数学对象是什么**：连续/离散、静态/动态、确定/随机、单体/网络、欧氏/成分/空间数据？
3. **硬结构是什么**：守恒、几何、逻辑、容量、时间、因果顺序、概率、边界条件或信息约束？
4. **证据条件是什么**：样本量、噪声、缺失、标签、观测频率；若存在待估参数或隐藏状态，再检查可辨识性；还要核对外部数据与算力。
5. **怎样判定成功**：题目交付量、误差、约束满足、稳定性、解释价值和运行成本分别如何衡量？

据此先做初步独立解析：仅当存在表示歧义时做 representation search（变量、状态、坐标、目标和约束的不同表示），仅当存在可利用结构时做 invariant search（守恒、单调性、对称性、尺度、可行域或不变量）；仅当存在真实模型选择或替代解释时做 counter-model test。若“现实结构 → 数学对象”仍有具体缺口，可按“推导援助”读取相关模式，帮助构造或重表示候选；候选形成后再压缩写入项目简报。每个主要模型或高影响结论应有合适参照，或记录明确的不适用理由；继承任务可复用上游参照，纯解析任务可用解析特例、极限、守恒、量纲或边界作参照。baseline 可取现状、朴素、松弛、解析特例或极限情形，不强制第二个复杂模型。候选可以来自经典模型、独立推导、自建目标与约束、机理—数据融合、分阶段子模型、跨模型组合、数值算法、仿真或可靠的新方法；数量随题目复杂度决定，不设固定上限或固定配额。

### 推导援助：按具体缺口取用模式

初步独立解析后，若“现实结构 → 数学对象”的翻译仍有具体断点，再按该断点读取 `derivation-patterns.md` 中相关模式。模式可以帮助构造或重新表示对象，也可以自由改写、跳过或不用；它不能覆盖题面事实、硬约束、数据语义、因果顺序或已确认的任务输出，不要求快照、额外 schema、artifact、专门术语或持久化审计记录。只保留能解决当前缺口的构造与验证部分，并用一个决定性拒绝条件、约束/事实回代、极限或小规模对照检查一致性；不能通过检查就继续独立推导或明确不采用。该援助不删减开放候选探索、基线、赛时预算、状态记录或外部历史边界。

## 2. 再借鉴：学习历史方案的选择思路

- **结构原语与模型卡**：初步独立解析后按需读取数学推导原语和相应模型卡；它们是候选表示启动器，不替代当前题推导。表现先验不参与候选生成或选模。
- **A1R/A1/A1Q**：仅在需要来源追溯、历史失败案例、历史方案比较、方法适配/反例或精确来源页码核验时定向读取，学习优秀方案如何识别题目结构、建立基线、组合子模型、处理约束并验证结论。A1R 的单队奖级未逐队匹配、材料非原始 PDF，状态必须按元数据表述。
- **M1 专家/名师评析**：重点提取“为何这样抽象、舍弃了什么方案、哪些假设最关键、常见解法错在哪里”。
- **M3 研究资料**：寻找可迁移的新算法、模型改进、适用条件和失败模式。
- **库外权威来源**：本地资料覆盖不足时，可查阅原始论文、官方算法文档或权威教材；不得因模型未收录而排除。

历史方案只能修改、扩展或反驳当前候选，不能直接替代对本题的独立分析。不要按历史获奖频率投票选模型，也不要复制往年固定组合。

## 3. 非穷举的检索起点

| 赛题结构示例 | 可先检索的模型线索（非首选、非穷举） | 可比较的简单基线 | 主要验证方向 |
|---|---|---|---|
| 离散资源配置 / 选址 / 调度 | 整数规划、多目标规划、动态规划、约束规划、网络流、元启发式或自建规则系统 | 贪心、随机、松弛、小规模穷举 | 可行性、上下界、最优性差距、规模扩展 |
| 连续动态系统 / 轨迹控制 | ODE/PDE、最优控制、模型预测控制、直接配点、状态估计、混合动力系统 | 基本数值积分、分段恒定控制 | 守恒、终端误差、网格收敛、控制可实施性 |
| 多指标评价 / 决策 | 统计降维、效用理论、排序学习、鲁棒决策、贝叶斯决策、组合赋权 | 等权、单指标、简单排名 | 权重与指标敏感性、排序稳定性、解释一致性 |
| 时间序列 / 预测 | 统计时序、状态空间、机器学习、深度时序、机理外推、集成与概率预测 | 朴素预测、移动平均、简单回归 | 前向回测、泄漏、区间覆盖、漂移与残差结构 |
| 高维 / 成分 / 模式识别 | 对数比几何、降维、核方法、树模型、概率图、表示学习或领域约束模型 | 简单规则、线性模型、基础聚类 | 数据空间假设、交叉验证、稳定性、可解释性 |
| 空间几何 / 参数反演 | 解析几何、非线性优化、贝叶斯反演、全局搜索、计算机视觉、可微仿真 | 粗网格、基本最小二乘 | 可辨识性、残差结构、参数不确定性、多解性 |
| 多任务耦合 | 分层模型、联合优化、多智能体、仿真—优化、数字孪生或自建组合 | 各子问独立求解 | 接口一致性、误差传播、整体增益、耦合必要性 |

这些线索只帮助检索。若题目结构指向表外方法，应直接扩展候选空间。

## 4. 后收敛：用本题证据选择模型

对每个重要候选记录并比较：

| 维度 | 必须回答的问题 |
|---|---|
| 结构匹配 | 模型假设是否与目标、变量、约束、数据空间和机理一致？ |
| 信息条件 | 若存在待估参数或隐藏状态，能否从现有数据辨识，样本量和精度是否足够；否则记录不适用？ |
| 相对价值 | 相比简单基线，它增加了什么可验证的能力或改进？ |
| 验证能力 | 是否存在样本外、边界、守恒、对照、消融或稳健性证据？ |
| 求解可靠性 | 是否收敛、可复现、满足约束，内存与运行时间是否适合现有算力？ |
| 赛时可实施性 | 按剩余时间、团队熟悉度和依赖可用性，最小可用实现、调试与验证各需多久？失败后能否回退到已运行的基线？ |
| 解释与交付 | 输出是否直接回答小问，能否解释关键机制和决策含义？ |
| 失败边界 | 在哪些数据、参数、极端场景或结构变化下会失效？ |
| 开放替代 | 是否遗漏了库外方法、自建模型或更简洁的等价表达？ |

对需要对照的主要模型或高影响结论，保留一个有意义的简单基线作为参照，但不规定主模型必须属于任何类别。对进入短名单的**具体候选实现**估算建模、编码、调试、求解和验证时间，并保留停止或降级条件；不要给整个模型族永久贴“低/中/高成本”标签，同一模型族会因规模、结构、求解器、团队经验和验证要求产生完全不同的成本。复杂度必须对应可观察的结构缺口、失败假设或高影响风险，并预先写明验证方式；不达 `continue_criterion` 时停止投入或回退。复杂度、传统或新颖程度都不是独立加分项；最终选择应由当前题目的可验证证据和赛时可实施性共同决定。选择证据与未决风险归 `modeling-brief.md`；运行清单的 `model_decisions` 只绑定任务到 selected/baseline run。

## 5. 赛时预算与最小证伪契约

候选探索必须服从当前赛题的剩余时间、可用算力和验证责任，但不使用统一的候选数、代码行数或运行秒数。显然简单题通常只需 baseline 与主模型。只有在下列任一风险触发时，才建立完整的 exploration deadline、fallback 和 continue 条件：存在两个以上竞争主模型、实现成本高、赛时完成不确定、非凸/随机失败风险，或外部依赖风险。触发后只为当前候选和当前赛时维护：

| 字段 | 含义 | 最低要求 |
|---|---|---|
| `exploration_deadline` | 本轮候选探索的停止时点 | 根据剩余赛时明确到可执行时点；到点即收敛，不因“还可能有更优模型”自动延长 |
| `fallback_baseline` | 截止时仍可交付的已运行基线 | 必须能回答对应小问，并保留同口径指标、约束检查和已知局限 |
| `continue_criterion` | 继续投入某候选所需的新证据 | 写成可观察条件，例如“小样本前向误差优于基线且约束无违反”，不能只写“效果较好” |

若触发预算契约，每个进入短名单的候选先做与其结构相匹配的最小可行性或证伪检查。检查可以是小规模实例、边界情形、量纲/守恒核对、适用时的参数可辨识性、松弛上下界、前向回测或低分辨率数值预跑；目标是尽早暴露决定性风险，不是为所有候选建立完整实现。若试验没有达到 `continue_criterion`，应停止投入或回退到基线。

候选状态只使用以下四类：

| 状态 | 判定证据 | 后续动作 |
|---|---|---|
| `viable` | 当前证据支持继续，且剩余时间允许完成必要实现与验证 | 进入更完整的建模、实现或对照 |
| `rejected_structural` | 模型假设、变量空间、约束或信息条件与题目存在结构性矛盾 | 记录关键证据并停止；不能仅因一次报错或不收敛使用此状态 |
| `unresolved_numerical` | 结构尚未被否定，但初值、尺度、离散、参数或求解器问题尚未解决 | 在预算内诊断；到截止时仍未解决则回退，不把它伪装成结构证伪 |
| `deferred_budget` | 可能有效，但已无足够时间或算力完成可信实现与验证 | 保留为备选或赛后方向，不挤占正式求解与写作时间 |

`selected` 是最终决策，不是运行状态。正式选模时，应在 `modeling-brief.md` 写明选择证据和仍未解决的风险，并将采用运行与基线的实际 ID 记入 `reproducibility.json`；只有确实影响最终选择的短名单运行才需要进入复现清单。

### 模型成熟度入口

按“回答型 → 基线型 → 经验证主模型 → 有证据的扩展模型”记录候选深度。升级必须同时说明结构缺口、扩展新增的可验证能力、同口径增益、计算成本和失败边界；仅在存在待估参数或隐藏状态时补充参数/数据可辨识性。模型名称高级不构成加分。DP、SPM、EKF、Sobol 等仅在对应残差、可观测性、非线性、空间或退化证据触发时比较，不能作为通用必选项。

## 6. 防止历史方案锚定

1. 先记录当前题目标、变量/状态、硬约束、数据/机理和子问接口的初步独立解析；再按具体缺口读取数学推导原语与相关模型卡，形成候选后补充可交付基线、适用时的 representation/invariant 搜索、counter-model test 和验证思路至 `modeling-brief.md`。论文写作/表现校准另按 playbook 处理。
2. `method-evidence.md` 不用于普通候选生成；只有来源追溯、历史失败案例或历史方案比较时才按需打开。A1R/A1/A1Q/M1 仅在需要历史来源、方法适配/反例或精确来源页码核验时定向读取。
3. 检索时同时寻找成功方案、被放弃方案和失败模式。
4. 把历史方法拆成可重组部件，例如表示、目标、约束、求解器和验证，而不是整套搬用。
5. 仅在存在真实模型选择或历史锚定风险时，检查“如果不用语料库中的常见模型，还能怎样表示问题”；若题目只有唯一解析式或规则表达，可明确记录该检查不适用。
6. 若库外或自建方案更符合本题，应优先采用，并补足理论来源与实验验证。

历史资料只用于校准、反证或补遗漏；不得以历史频率替代当前题证据，不复制摘要或固定组合，也不要求固定候选数量。
