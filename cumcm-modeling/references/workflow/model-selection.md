# CUMCM baseline-first / gap-driven 开放式模型探索与证据收敛指南

> **核心原则**：采用 baseline-first、gap-driven 顺序：先由当前赛题结构闭合可检验 baseline，再按关键缺口开放模型探索。Skill 内置蒸馏规则、数学原语、模型卡与按需核验的外部来源用于启发、反证和校准，不是模型白名单，也不限定探索空间。

本文件负责候选探索、结构充分性与缺口检查及证据比较。

---

## 1. 先闭合：结构解析与可检验 baseline

在查看历史解法或扩展候选前，先独立回答：

1. **目标是什么**：解释、评价、预测、识别、反演、优化、控制、仿真还是决策？
2. **数学对象是什么**：连续/离散、静态/动态、确定/随机、单体/网络、欧氏/成分/空间数据？
3. **硬结构是什么**：守恒、几何、逻辑、容量、时间、因果顺序、概率、边界条件或信息约束？
4. **证据条件是什么**：样本量、噪声、缺失、标签、观测频率；若存在待估参数或隐藏状态，再检查可辨识性；还要核对外部数据与算力。
5. **怎样判定成功**：题目交付量、误差、约束满足、稳定性、解释价值和运行成本分别如何衡量？

据此先做初步独立解析：对非优化任务，representation search 主要由表示歧义触发；**对显式优化/设计任务，还由搜索维度、变量耦合、评价成本和表示偏差触发，即使题意语义本身没有歧义。** representation 的目标是保留关键决策自由度并采用更可搜索的替代表示，而不是为了降维而降维。仅当存在可利用结构时做 invariant search（守恒、单调性、对称性、尺度、可行域或不变量）；仅当存在真实模型选择或替代解释时做 counter-model test。若“现实结构 → 数学对象”仍有具体缺口，可按“推导援助”读取相关模式，帮助构造或重表示。随后先实现一个可检验的 baseline，并用题目输出、约束回代、边界/特例或适用的误差指标检查它。baseline 可取现状、朴素、松弛、解析特例或极限情形，不强制第二个复杂模型；纯解析、唯一结构或简单确定性任务可在此记录不适用的比较项。

### Baseline comparability rule

baseline 可以承担不同作用，但用于“性能优于 baseline”“模型改进幅度”或 `fallback_baseline` 的参照，必须能在同一题意口径下完成真实任务，并产生与 selected 可直接比较的必需输出、约束与评价指标。若某个松弛、解析特例、极限情形或简化参考不能完成真实任务，只把它作为 `diagnostic reference`、界或结构检查使用；不得用它单独证明 selected 的性能提升，也不得把它当作赛时可交付 fallback。无需新增 role、schema 或运行记录类型，按实际作用在现有说明中区分即可。

### Baseline Structural Sufficiency Check

`baseline` 的职责是建立可检验参照，不自动拥有 `selected` 资格。baseline 闭合后、进入 Gap Check 前，回看 `problem-analysis` 已确认的答案敏感结构：若层级/重复测量、删失/事件观测、时间顺序、守恒/几何、特殊数据空间、交互/耦合、测量误差、真实决策约束或信息集中的任一结构会改变必需输出、决策、误差或解释，但当前方案尚未在合适层级处理它，则把该项显式转入结构 Gap/数据 Gap。处理方式可落在表示/primary mechanism、误差与不确定性、切分/验证设计或 decision layer；只有结构确实改变核心状态关系或估计机制时，才要求升级 primary model。不能因 baseline 已能运行直接停止，也不能因发现结构就自动增加主模型复杂度。

结构充分性不要求复杂模型，也不要求每题至少一个“高级机制”。若最小检查显示额外结构在本题尺度下对核心输出可忽略，或题目本身确属简单确定性/唯一结构任务，baseline 可直接成为 selected。判断目标是“最小充分”，不是“至少复杂到某级”。

### 推导援助：按具体缺口取用模式

初步独立解析后，若“现实结构 → 数学对象”的翻译仍有具体断点，再按该断点读取 `derivation-patterns.md` 中相关模式。模式可以帮助构造或重新表示对象，也可以自由改写、跳过或不用；它不能覆盖题面事实、硬约束、数据语义、因果顺序或已确认的任务输出，不要求快照、额外 schema、artifact、专门术语或持久化审计记录。只保留能解决当前缺口的构造与验证部分，并用一个决定性拒绝条件、约束/事实回代、极限或小规模对照检查一致性；不能通过检查就继续独立推导或明确不采用。该援助不删减开放候选探索、基线、赛时预算、状态记录或外部历史边界。

## 2. Gap Check：按缺口开放候选

baseline 闭合后，逐项判断是否存在关键 Gap。Gap 至少覆盖四类语义问题：

- **题意 Gap**：baseline 是否遗漏必需输出、决策动作、题面硬约束或跨问接口？
- **结构 Gap**：守恒、几何、动态、交互、非线性、随机性或表示是否会改变答案或解释；**对显式优化还包括关键决策自由度被人为固定、结构族过窄、变量交互未进入搜索。**
- **数据 Gap**：观测噪声、缺失、样本量、参数/状态可辨识性或数据空间假设是否足以支持结论？
- **结果 Gap**：误差、稳定性、边界、敏感性、可行性或机制解释是否不足以支撑所需答案；**对显式优化还包括当前 incumbent 与可靠松弛/上界、小规模精确解、原变量局部动作或明显不同结构族之间仍存在值得追踪的改进余量。**

#### Representation / Decision Adequacy 作为现有 Gap 的触发证据

以下现象不新增第五类 Gap，而是用于判断现有“结构 Gap / 结果 Gap / 题意 Gap”的来源：

- 最优结果持续贴人工上下界；
- 多个方案在正式目标上近乎等价；
- 增加自由度后策略不变；
- 离散表示明显粗于底层连续结构；
- 自建目标对关键动作近似单调、平坦或由人为分段制造极值；
- 合理偏好变化导致方案结构性切换；
- 平均预测指标几乎不变，但最终任务相关的决策行为明显变化。

触发后先定位是 data-limited、representation-limited、objective-limited、metric-limited 还是 search-limited，再按原有 Gap 责任路由处理。不得把“输出太简单”本身当作模型 Gap。

每个疑似 Gap 都回答四个语义问题：Trigger（什么证据触发）、Effect（会改变哪个必需输出/决策/误差/解释）、Evidence（用什么最小检查确认）、Cost（实现、求解和验证代价）。这四项是判断问题，不是固定表格或新增 schema。若没有关键 Gap，先确认 baseline 已通过 Structural Sufficiency Check；随后检查是否仍存在可观测的结构性改进余量，例如系统性残差、明显界差距、未利用的交互/耦合或稳健性缺口。若存在，将其归入现有 Gap 并只做针对性扩展；若不存在，则停止模型扩张，把预算转向求解、验证和解释。

### 缺口处置判定

Gap 不自动等于模型扩展。先按责任选择去向：题意映射错误→修正题意；数据/信息不足→补数据、情景化或收窄主张；求解不足或验证不足→补强求解或验证；只有模型/表示缺口已确认、能由新增模型/表示/机制在现有证据条件下修复，并通过最小证据检查时，才开放候选空间。最后一类仍可读取模型卡、采用库外方法、自建模型、机理—数据融合、分阶段模型或组合表示；候选数量由缺口、证据和赛时决定，不设固定上限。默认一次只改变一个可归因的主要表示、机制、耦合或目标/约束结构，并通过同口径对照或消融完成最小证伪；对显式优化，**一个“主要变化”可以是一组必须共同释放的耦合决策自由度或一个新的 design representation，不要求逐变量串行放开；只需保证其作用能够通过同口径对照、局部消融或边界试验解释。**仅更换同族算法、求解器或调参不视为模型扩展，除非它直接解除已经确认的求解 Gap。只有机制不可分耦合时才共同加入，并说明不可分原因。若检查未显示预期作用，停止该扩展或回退 baseline。

### Component Role Collapse：先去重，再增加复杂度

对拟进入正式主链的每个实质组件，先标记其唯一主要角色，不要求生成新 schema：

- `representation / measurement`：状态、坐标、观测过程、特征空间或误差表示；
- `primary estimator / mechanism`：估计同一个核心状态、概率、响应或动力关系；
- `decision / optimization layer`：把预测/状态转换为风险、目标、约束和决策；
- `solver`：数值积分、DP、MILP solver、GA/PSO、采样或训练算法；
- `diagnostic`：相关性、残差、探索性聚类、可视化或显著性诊断；
- `baseline / challenger / validation`：用于比较、消融、稳健性或反证，不属于最终主链的并列机制。

同一中间目标原则上只允许一个 `primary estimator / mechanism` 进入 selected 主链。若两个方法输出同一概率/状态/评分，应先做同口径比较并选一个；未选者保留为 challenger 或 baseline，而不是用“方法 A + 方法 B + 方法 C”制造深度。若后续扩展模型已包含前一模型的必要能力并通过验证，默认 `replace-over-stack`：前一模型退回 baseline/challenger，主链只保留扩展模型。

只有满足以下条件时才允许真正的 ensemble/stacking 作为主模型：组合具有清晰单一输出角色；训练/验证无泄漏；在相同数据切分与指标上稳定优于最佳单模型或显著改善关键校准/尾部风险；并通过最小消融证明组合贡献。否则多个分类器/回归器同时出现仍按竞争候选处理。

诊断统计、预处理、求解器、超参数优化器、可视化工具不能被计作“新增模型”；它们只需解释自己为何对主链必要。G1-H 的 selected 路线不得使用未决的“A 或 B”“A/B/C 均可”作为最终方案；若仍未决，必须给出决定实验与选择条件，并保持候选状态而非 selected。

## 3. 再借鉴：按缺口补充外部证据

先依据 Gap 的结构匹配、数据条件和验证可行性，再深读进入短名单的 Method Cards；不要预加载全部 sibling model cards，也不要在同一任务中重复阅读内容未变化的卡片。候选数量保持开放，由本题证据和赛时预算决定。

- **内置蒸馏经验**：数学原语、推导模式与模型卡是候选表示启动器，负责提供结构化的选择逻辑、失败边界和验证接口，不替代当前题推导。
- **外部公开来源**：仅在理论来源、历史失败案例、方案比较、方法适配/反例或精确出处会改变论证时定向检索；优先原始论文、官方算法文档、权威教材及可核验的竞赛公开材料。
- **使用边界**：外部方案只能修改、扩展或反驳当前候选，不能直接替代对本题的独立分析；不得按历史出现频率投票选模型，也不得复制固定模型组合。

## 4. 非穷举的检索起点

Gap 确认后，根据其数学结构按需读取对应 Method Card；模型卡仅作为候选启动器，必须同时允许库外、自建、重表示及更简单等价方案，禁止将题型关键词直接映射为固定模型。

### Cross-question Shared Core + Delta

若后续小问与前问共享同一核心推断目标、状态定义、决策目标或正式约束接口，先继承已验证的主模型，只描述本问新增的 `delta`：新增协变量、状态、约束、风险项、不确定性或自由度，并验证该 delta 是否改变结果。不要因题号变化重新开启一套同功能模型族。

#### Interface-preserving inheritance

`Shared core` 的判断以数学接口而不是模型名称为准。对真实依赖边，至少比较：

1. `canonical object`；
2. `response/state representation`；
3. `core relation`；
4. `stochastic / measurement layer`；
5. `downstream interface`。

若 1–4 实质不变，只因后问使用不同合法信息集、增加协变量/约束/风险或重新估计参数，则属于 `shared core + delta / re-estimation`，不得重新开启同功能主模型族。

若 response/state transform、核心函数族、时间/空间参数化、随机结构或观测误差定义发生变化，默认视为 `core replacement`。不能把“系数重新拟合”和“数学结构替换”混为一谈。

若新增 delta 的输出会直接进入下游决策，保留/删除 delta 的主证据应与最终任务接口一致。平均预测误差、拟合优度或总体分类指标仍需报告，但不得独占保留门槛；可按题意与预声明风险补充 decision loss/regret、关键约束裕度、决策边界附近校准、方案切换稳定性或题面明确关键区域的可靠性。

任何 task-level metric 必须在比较候选前由题面、机制或 G1 主导风险预先确定；不得观察结果后再挑选最有利的子群、阈值或指标。若 task-level 指标改善但整体校准、稳定性或主要预测质量明显恶化，不得仅凭局部决策收益保留复杂模型。

只有出现下列至少一种实质变化，才允许替换共享核心：
1. 目标量或决策接口改变；
2. 数据生成/观测结构改变，例如从横截面变为删失事件、从单一静态变量变为真实时序；
3. 原模型的关键假设被新数据/新约束明确破坏；
4. 新问需要原模型无法表达的状态、交互或不确定性；
5. 同口径最小实验显示替换模型在该问的主任务评价量上带来稳定、可解释且可复现的增益；若模型输出进入下游决策，主任务评价量应包含预先声明的决策相关证据，而不是只比较平均预测误差。

换核采用最小 `replacement burden`：

- 优先只改变一个主要接口轴；
- 同时改变多个接口轴时，说明它们为何由同一个结构 Gap 不可分地触发；
- 必须用 `inherited core` 作为后问的直接 baseline，在后问同口径任务量上比较；
- 只要 `inherited core + 一个局部 delta` 已能修复缺口，就不允许整套重写；
- 换核后仍应继承所有没有被失效证据否定的上游事实、约束和不确定性。

换核时必须写清：

`原接口指纹 → 失效证据 → 修改的接口轴 → 保持不变的接口 → 同口径比较结果`。

若不能指出具体失效证据，只因后问题号、输出形式或模型偏好不同而重写核心，保持 `inherited core`。

## 5. 后收敛：用本题证据选择模型

对每个重要候选记录并比较：

| 维度 | 必须回答的问题 |
|---|---|
| 结构匹配 | 模型假设是否与目标、变量、约束、数据空间和机理一致？ |
| 信息条件 | 若存在待估参数或隐藏状态，能否从现有数据辨识，样本量和精度是否足够；否则记录不适用？ |
| 相对价值 | 相比简单基线，它增加了什么可验证能力；这种增益是否落在题目真正要求的解释、预测、决策、约束或策略层，而不是只改善中间统计量？ |
| 验证能力 | 是否存在样本外、边界、守恒、对照、消融或稳健性证据？ |
| 求解可靠性 | 是否收敛、可复现、满足约束，内存与运行时间是否适合现有算力？ |
| 赛时可实施性 | 按剩余时间、团队熟悉度和依赖可用性，最小可用实现、调试与验证各需多久？失败后能否回退到已运行的基线？ |
| 解释与交付 | 输出是否直接回答小问，能否解释关键机制和决策含义？ |
| 失败边界 | 在哪些数据、参数、极端场景或结构变化下会失效？ |
| 开放替代 | 是否遗漏了库外方法、自建模型或更简洁的等价表达？ |

### Innovation Opportunity Check（非 Gate、非 KPI）

在结构充分性通过且存在真实提升余量时，允许做一次轻量创新扫描。创新候选至少落到以下一种问题特定杠杆：

1. `representation`：更符合几何、成分、网络、状态或尺度的表示；
2. `mechanism / observation`：加入有证据的层级、删失、测量误差、反馈、守恒或状态转移；
3. `decision interface`：目标函数、约束、风险或多阶段决策更直接对应题面动作；
4. `coupling / uncertainty propagation`：真实跨问接口与上游误差进入下游结论；
5. `analytical structure`：利用单调、凸性、界、临界点、可分解性等得到更强解释、降维或可靠求解。

每个创新候选只回答四件事：baseline 漏了什么；新增结构是什么；预期改变哪个必需输出/稳定性/解释；用什么同口径对照或消融确认。若答案只能表述为“算法更先进、模型更多、参数更多、文献更新”，不视为创新理由。若没有可验证的创新杠杆，停止扩展并把预算用于验证和结果解释。创新扫描不以“让结果更非平凡”为目标。新的 representation 或 decision interface 只有在修复已观察到的结构/结果缺口、提高任务对齐性或增强可验证解释时才算有效创新；若替代表示只让输出更复杂但没有新增稳定信息，应回退。

### Optimization Potential Check（显式优化轻量筛查）

所有显式优化任务先做轻量筛查，不是独立模型门，也不要求增加固定数量的候选：核对原始决策变量与真正开放变量、人工固定及理由、搜索族/表示覆盖、变量交互，以及评价误差和相对上界/松弛/理想参照显示的改进余量。只有发现表示、搜索、交互或评价风险时，才进一步展开替代表示、代理评价、结构族或更深搜索；仍须回到原始目标与全部硬约束验收。

- 原始决策变量与实际仍开放的变量是否一致；哪些变量被固定、绑定或由生成器隐含，理由是否来自题面或可验证的结构，而非方便求解；
- 人为结构约束与题面硬约束是否分开，搜索族/参数化覆盖了什么、遗漏了什么，表示偏差会不会排除有价值方案；
- 目标对动作的响应性与变量间相互作用，评价成本及其误差是否足以支持排序；
- 自建目标/评分是否具有足够的决策区分能力：检查单调边界寻优、大面积平坦、多解等价、人工分段极值和偏好不可辨识；这些问题属于 decision interface / representation 风险，不应通过增加求解器掩盖；
- 相对上界、松弛、理想参照或小规模精确解显示的改进余量，是否值得继续扩大搜索；
- 后问新增自由度如何进入搜索、继承上问可行解或基线，以及新增自由度是否确实被系统探索。

当发现表示过窄、评价昂贵、目标退化、偏好不可辨识、先独立排序或后续任务沿用同一生成器时，默认只做一次最小、结构独立的替代表示探针，例如另一种约束表达、多目标/词典序表达、连续关系后再运营压缩、原变量局部动作或明显不同的结构族。若探针仍显示改进余量很小或支持相同的简单结论，允许据此收敛；不得为了获得更丰富答案继续扩张。只有存在两个彼此独立、均由题面证据触发的未决结构风险时，才在赛时预算允许下继续第二个探针。若无改善，也要记录针对新增自由度的搜索证据与停止依据。**停止扩大优化搜索时，停止依据不能只来自当前生成器内部的代理值、前缀历史或同一结构族重复搜索。若当前表示严格窄于原始可行域，至少应有一种不共享同一表示偏差的轻量证据，例如可靠松弛/界、小规模精确解、原变量 `add/delete/swap/perturb/repair`、或明显不同的结构族。若这些证据均显示改进余量很小或当前结果已接近可靠界，再收敛到当前表示。**

对需要对照的主要模型或高影响结论，保留一个有意义的简单基线作为参照，但不规定主模型必须属于任何类别。对进入短名单的**具体候选实现**估算建模、编码、调试、求解和验证时间，并保留停止或降级条件；不要给整个模型族永久贴“低/中/高成本”标签，同一模型族会因规模、结构、求解器、团队经验和验证要求产生完全不同的成本。复杂度必须对应可观察的结构缺口、失败假设或高影响风险，并预先写明验证方式；不达 `continue_criterion` 时停止投入或回退。复杂度、传统或新颖程度都不是独立加分项；最终选择应由当前题目的可验证证据和赛时可实施性共同决定。选择证据与未决风险归 `modeling-brief.md`；运行清单的 `model_decisions` 只绑定任务到 selected/baseline run。

### 人工可审查输出

完整整题、完整大纲、完整结果包或用户要求计算前审查时，主模型正式实现前必须把当前选择展开为 `PROJECT_ROOT/preliminary-modeling-report.md`，供 G1-H 人工审查。报告不是 `modeling-brief.md` 的扩展，也不是运行事实源；它按每个真实任务呈现核心项：题意/必需输出、可检验 baseline、Gap Check 与升级决定、模型与算法流程、关键假设和决定性验证。真实竞争方案、可辨识性、复杂敏感性、跨问接口、优化搜索或回退条件只在相应风险触发时展开。

报告必须把模型与算法分开：模型说明变量、关系、目标、约束和概率/机理结构；算法说明解析推导、数值积分、训练、优化器或采样设置。候选数量和报告篇幅随题目复杂度自适应；没有真实竞争方案时不为满足格式虚构候选，也不引入意图匹配或模型质量评分。人工未明确 `APPROVED` 前保持 `PENDING`，不得正式计算；`REVISE` 时回到意见影响的最早阶段，修改后重新生成报告。

## 6. 赛时预算与最小证伪契约

候选探索必须服从当前赛题的剩余时间、可用算力和验证责任，但不使用统一的候选数、代码行数或运行秒数。显然简单题通常只需 baseline 与主模型。只有在下列任一风险触发时，才建立完整的 exploration deadline、fallback 和 continue 条件：存在两个以上竞争主模型、实现成本高、赛时完成不确定、非凸/随机失败风险，或外部依赖风险。触发后只为当前候选和当前赛时维护：

| 字段 | 含义 | 最低要求 |
|---|---|---|
| `exploration_deadline` | 本轮候选探索的停止时点 | 根据剩余赛时明确到可执行时点；到点即收敛，不因“还可能有更优模型”自动延长 |
| `fallback_baseline` | 截止时仍可交付的已运行基线 | 必须能回答对应小问，并保留同口径指标、约束检查和已知局限 |
| `continue_criterion` | 继续投入某候选所需的新证据 | 写成可观察条件，例如“小样本前向误差优于基线且约束无违反”，不能只写“效果较好” |

若触发预算契约，每个高成本或高失败风险候选在进入完整实现前，先识别最可能使该候选失效的一个或少量 `load-bearing risk`，再设计最便宜且有区分度的 probe 尝试证伪。风险可来自信息/数据条件、关键假设、可辨识性、输出退化、可行域、规模、非凸/随机稳定性或实现依赖；只检查真正会改变候选去留的风险，不机械跑完整风险清单。probe 可以是小规模实例、边界情形、量纲/守恒核对、参数可辨识性、松弛上下界、前向回测或低分辨率预跑。只有主要承重风险未被证伪且达到 `continue_criterion`，才继续投入；否则停止、降级或回退 baseline。

候选状态只使用以下四类：

| 状态 | 判定证据 | 后续动作 |
|---|---|---|
| `viable` | 当前证据支持继续，且剩余时间允许完成必要实现与验证 | 进入更完整的建模、实现或对照 |
| `rejected_structural` | 模型假设、变量空间、约束或信息条件与题目存在结构性矛盾 | 记录关键证据并停止；不能仅因一次报错或不收敛使用此状态 |
| `unresolved_numerical` | 结构尚未被否定，但初值、尺度、离散、参数或求解器问题尚未解决 | 在预算内诊断；到截止时仍未解决则回退，不把它伪装成结构证伪 |
| `deferred_budget` | 可能有效，但已无足够时间或算力完成可信实现与验证 | 保留为备选或赛后方向，不挤占正式求解与大纲综合时间 |

`selected` 是最终决策，不是运行状态。正式选模时，应在 `modeling-brief.md` 写明选择证据和仍未解决的风险，并将采用运行与基线的实际 ID 记入 `reproducibility.json`；只有确实影响最终选择的短名单运行才需要进入复现清单。

### 模型成熟度入口

按“回答型 → 基线型 → 经验证主模型 → 有证据的扩展模型”记录候选深度。升级必须同时说明结构缺口、扩展新增的可验证能力、同口径增益、计算成本和失败边界；仅在存在待估参数或隐藏状态时补充参数/数据可辨识性。模型名称高级不构成加分。DP、SPM、EKF、Sobol 等仅在对应残差、可观测性、非线性、空间或退化证据触发时比较，不能作为通用必选项。

## 7. 防止外部方案锚定

1. 先记录当前题目标、变量/状态、硬约束、数据/机理和子问接口的独立解析，必要时完成 representation/invariant 搜索；闭合可交付 baseline 并完成 Gap Check 后，才按具体缺口读取数学推导原语、相关模型卡或外部来源。
2. 外部资料不用于普通候选生成；只有理论来源、失败案例、方案比较、方法适配/反例或精确出处会改变当前论证时才定向检索。
3. 检索时同时关注成功条件、失败模式和不可迁移边界。
4. 把外部方法拆成可重组部件，例如表示、目标、约束、求解器和验证，而不是整套搬用。
5. 仅在存在真实模型选择或锚定风险时，检查“如果不用常见模型，还能怎样表示问题”；若题目只有唯一解析式或规则表达，可明确记录该检查不适用。
6. 若库外或自建方案更符合本题，应优先采用，并补足理论来源与实验验证。

外部资料只用于校准、反证或补遗漏；不得以历史频率替代当前题证据，不复制摘要或固定组合，也不要求固定候选数量。
