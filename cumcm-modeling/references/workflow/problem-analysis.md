# CUMCM 赛题理解与子问题拆解规范

> **适用阶段**：竞赛阶段 A（赛题初读、任务识别、依赖分析与选题建议）  
> **核心原则**：不盲目套用模型，将题目中的每一个自然语言动词转化为可验证的数学任务。

本文件先完成题面结构画像，再把证据计划写入项目简报。

---

## 1. 赛题信息要素提取矩阵

### 1.0 先建立“本题任务与数值交付约束表”（题面本地约束，不是 R 规则层）

在抽象模型之前，逐页检查题面及附件，记录会改变建模和求解交付的事实：每一问必须给出的具体数值/方案/决策、输入附件与数据字段、题目明确硬约束、单位/坐标/口径要求、用户明确要求的输出文件等。建议使用以下表格，并把每一项绑定到题面或附件的页码、段落或文件名。

| 约束项 | 题面/附件原文位置 | 本题要求 | 对应产物/检查 | 未满足时的风险 |
|---|---|---|---|---|
| 每问数值/方案交付 |  |  | 各子问具体答案或输出文件 | 遗漏子问导致解题不完整 |
| 输入数据与字段语义 |  |  | 附件表、字段口径与单位 | 数据理解错误导致模型偏差 |
| 题目明确硬约束 |  |  | 物理限制、守恒、几何干涉 | 违背硬约束导致解不可行 |
| 单位与定义口径 |  |  | 标准单位、坐标系、符号定义 | 量纲不统一或量级错误 |
| 用户指定产物格式 |  |  | 指定 metrics JSON 或导出格式 | 不符合提交交付约定 |

题面约束不能等到最终审计才补录；提交前再按当前届官方/赛区规则核对格式与合规要求。出现文字冲突时，先核对来源权威性、版本、适用范围和明确的优先级，并记录裁决依据；不同对象或阶段的要求分别适用，不能机械取更严格者而缩小题面允许的可行域。若同一事项仍有无法消解且实质影响答案的冲突，应定向澄清，并继续不依赖该裁决的工作。


在通读赛题时，必须覆盖研究对象、核心任务、硬性约束、输入数据、交付成果五类信息。可用表格、笔记、关系图或自然语言承载；下表只是便于核对的推荐形式，不强制使用五维表：

| 维度 | 审查要点 | 常见陷阱与注意项 |
|---|---|---|
| **研究对象 (Objects)** | 物理实体、业务主体、变量边界、系统环境 | 避免混淆微观个体（单车/单人）与宏观统计量（区域流量） |
| **核心任务 (Tasks)** | 题目中的明确动词（如“评价”、“预测”、“优化”、“控制”、“反演”） | “评价”需构建指标体系，“优化”需明确目标与约束，“反演”需机理方程 |
| **硬性约束 (Constraints)** | 物理定律、资源上限、时间窗口、几何干涉、政策红线 | 隐含约束容易遗漏（如非负性、整数性、总和为1、能量守恒） |
| **输入数据 (Data)** | 数据类型、采样频率、维度、缺失率、时空对齐 | 区分题目已知数据、自主采集数据与模型推导参数 |
| **交付成果 (Deliverables)** | 必须回答的具体数值、表格、曲线、策略方案 | 必须逐一对应题目小问，不得遗漏任何子问的量化输出 |

### 1.1 数据集初步预审与结构诊断（按需触发）

对包含复杂表格、多 sheet Excel、时序或多维度数据（如存在隐藏列、合并表头、缺失值、时间截断或可能的数据泄漏风险）的赛题，按需运行专用审计脚本：

```bash
python3 <SKILL_ROOT>/scripts/audit_dataset.py <dataset_path> [--inspect] [--time-column <col>] [--prediction-cutoff <cutoff>]
```

该工具输出字段类型、缺失率、时序连续性与前瞻性泄漏风险诊断；普通清洁小表或无需复杂诊断的赛题不必强制执行。

## 2. 数学结构识别（不要由题目动词直接套模型）

信息提取后，先建立结构画像，并在必要时完成 representation/invariant 推导；随后闭合可检验 baseline、执行 Gap Check，只有存在关键缺口时才进入候选模型探索。每项允许“混合”或“尚待验证”，不能强行归入单一题型。

| 结构维度 | 需要判断的问题 | 对候选空间的影响 |
|---|---|---|
| 变量与状态 | 连续、整数、类别、集合、图节点/边，还是随时间变化的状态？ | 决定代数、组合、网络或动态表示的必要性 |
| 时间结构 | 静态、离散时段、连续动态、事件驱动，是否有滞后和反馈？ | 区分静态优化、时序、控制、离散事件与混合系统 |
| 随机性 | 不确定性来自观测噪声、参数、过程随机性还是情景未知？ | 区分确定模型、随机/鲁棒优化、概率模型与仿真 |
| 约束结构 | 线性/非线性、凸/非凸、逻辑/整数、守恒/几何、局部/全局？ | 决定求解难度、松弛方式、全局性与验证重点 |
| 层级与主体 | 单主体、多个相互作用主体、上下层决策还是竞争合作？ | 检查博弈、双层规划、多智能体或分层模型是否必要 |
| 数据空间 | 独立表格、时序、空间、网络、图像、文本、成分或删失数据？ | 决定预处理、距离、损失函数和验证切分是否成立 |
| 推断目标 | 描述、比较、解释、预测、反演、因果、优化还是控制？ | 明确评价指标，避免把相关预测误写成因果结论 |
| 耦合关系 | 子问题能否独立，还是共享状态、参数、约束和误差？ | 决定分阶段求解、联合建模与误差传播方式 |

预测任务先区分已有观测重构、未见样本预测和训练范围外推，再按 `validation-and-sensitivity.md` 的证据要求检验；不以是否具有机理方程决定它能否用于预测。

### 观测过程与决策信息集（仅在会改变模型时展开）

结构画像完成后，对会进入主模型或关键决策的变量做一次信息时序检查。至少区分：`latent/state`（真实但不可直接观测）、`observed_pre_decision`（决策时已可获得）、`observed_post_decision`（执行动作后才获得）、`outcome/label`（结果或监督标签），并确认记录所属层级（个体/批次/时点/重复测量）。无需为所有字段建立新 schema，只对可能改变模型的变量记录。

- 前置决策模型不得直接使用 `observed_post_decision` 或由 outcome/label 派生的信息；确需使用时，必须改为决策时可获得的代理/预测量，并单独验证代理误差。
- 离散采样下的“第一次观测到越过阈值”不自动等于真实事件时点；若真实穿越只能定位在两个观测之间，应检查区间删失/事件观测机制，或证明端点近似不会改变结论。
- 同一对象多次观测、同次实验多次测量、批次/场景嵌套等层级必须在切分、误差结构或模型中被处理；不能因数据表“一行一个样本”默认独立同分布。
- 当测量误差、选择机制或检测下限会改变阈值、排序、分类或最优决策时，把“真实状态 → 观测过程 → 决策输入”作为结构 Gap 的候选，而不是仅在事后敏感性分析中补噪声。

### 赛题意图锚点

在候选模型探索前，为每个任务记录题目原始任务动词、必须交付的量、主要可用数据、硬约束、与其他小问的真实依赖、当前判断的数学任务类型，以及支持该判断的题面证据。每问都要能回答“题目真正要求什么、模型将输出什么、两者是否一一对应”。这些锚点是后续 `preliminary-modeling-report.md` 的上游依据，不能在报告阶段凭模型偏好补写。

### 交付形式与潜在数学结构分离

题目要求的最终展示形式不自动等于底层模型的真实结构。对分组、分档、等级、有限方案或统一策略类交付，先判断离散结构属于哪一种：

1. **结构性离散**：类别、状态或规则本身由题面、物理、逻辑或业务机制明确给定；
2. **运营性离散**：底层状态—决策关系天然连续，离散结果只是为了实施、管理、解释或提交而进行的近似压缩。

若属于结构性离散，直接建模离散结构；若属于运营性离散，优先先识别连续关系/个体策略/连续边界，再判断如何压缩为题目要求的有限方案。不得仅因题面要求“分组/分档”就默认把切点本身作为 primary modeling mechanism，也不得为了得到多个组而固定组数。

把该判断作为现有任务锚点或 Gap Check 的自然语言证据保存，不新增 schema 字段。

完成结构画像后，先不受简报字段或历史卡片限制做必要的自由推导：一般任务仅在表示存在歧义时搜索 representation；**显式优化/设计任务还应在原始决策空间高维、交互显著、评价昂贵，或人为生成器/参数化可能过早冻结有价值自由度时，主动比较更可搜索且可回代验收的 representation**。存在可利用结构时再搜索 invariant；仅有真实模型选择或替代解释时才做 counter-model test。若主要结论依赖自建效用、风险、评分或加权目标，在进入正式候选前先做最低成本的方向性检查：目标对关键动作是否具有区分度，是否天然单调贴边界，是否存在大面积平坦区，或是否由人为分段/权重产生主要极值。若存在上述信号，将其记录为 decision-interface Gap，而不是直接交给更强求解器。随后闭合一个可检验 baseline，再做 Gap Check，并先判断缺口处置类别：题意映射错误先修题意，数据/信息不足先补数据、情景化或收窄结论，验证不足或结果证据不足先加强验证，求解不足先补强求解；只有模型/表示缺口能在现有证据条件下由新增模型、表示或机制修复时才开放候选。默认单步增加一个主要机制并最小证伪，不用叠模型绕过数据、验证或求解责任。没有关键 Gap 时停止模型扩张。每个主要模型或高影响结论应有合适参照，或记录明确的不适用理由；继承任务可复用上游参照，纯解析任务可用解析特例、极限、守恒、量纲或边界作参照。将目标、变量/状态、硬约束、数据/机理、子问接口、baseline、Gap Check、缺口处置、候选表示和验证思路压缩保存到 `modeling-brief.md`，作为读取内置模型卡或补充外部来源前的可观察 G1 门。简报完成后，只有针对已确认且可由模型/表示修复的缺口才按需读取数学推导原语与相关模型卡；外部方案仅在理论来源、失败案例、方案比较或方法适配反例会改变论证时定向检索。外部资料只能校准、反证或补遗漏，不得替代当前题的独立结构草案；开放候选、库外方法和组合模型能力保持可用，不规定固定候选数量。

## 3. 子问题依赖关系与接口

只有当参数、状态、数据、约束或误差确实在任务之间传递时，才建立有向无环图（DAG），并标注实际传递对象。若任务彼此独立，使用“任务—输入—输出”映射即可，不强制绘制 DAG：

```text
[赛题背景与原始数据] 
       │
       ▼
【数据审计与预处理】 ──> (清洗后数据字典)
       │
       ├─────────────────────────────────────────┐
       ▼                                         ▼
【任务 A：机理/基线模型构建】               【全局参数估计与标定】
       │                                         │
       ▼                                         ▼
 (任务 A 解 / 状态初值) ───────────────> 【任务 B：多目标/动态优化模型】
                                                 │
                                                 ▼
                                        (任务 B 策略解 / Pareto前沿)
                                                 │
                                                 ▼
                                       【任务 C：动态环境/稳健性检验】
                                                 │
                                                 ▼
【综合评价、推广与结论】
```

### 跨问数学接口指纹

对每一条真实依赖边，不只写“传递参数/状态/模型”，还要能够在自然语言中定位以下接口：

- `canonical object`：上下游共享的真实数学对象；
- `scale / representation`：该对象的尺度、坐标或变换；
- `core relation`：承担状态、机理或预测的主关系；
- `stochastic / measurement layer`：会影响下游的随机性、误差、删失或观测过程；
- `information set`：后问在决策/预测时合法可用的信息；
- `downstream output interface`：上游实际交给下游的参数、状态、概率、边界、预测分布、可行域或不确定性。

若后问仍研究同一个 `canonical object`，只改变信息口径、增加协变量、约束、风险项或决策层，默认保持前四项结构连续；必要时可在同结构下重新估计参数或对未知状态做边际化。若需改变 `representation`、`core relation` 或 `stochastic/measurement semantics`，则在进入候选模型前显式标为 `core-replacement candidate`，并交由 `model-selection.md` 的换核条件判断。

独立分支不建立该合同，不为了形式连续强行继承。

对依赖图中的每条边标注实际传递对象及其数学接口；没有数学或题意依据的子问题标记为独立分支，不强行连接。后问若只需重新估计同一结构的参数，应明确写成“shared structure + re-estimation”，不得误报为全新模型。

## 4. 选题决策与风险评估矩阵

当团队在 A/B/C/D 题之间权衡时，先按证据状态记录以下 6 维指标，不把未经标定的 1~5 分当作客观结论：

| 维度 | 记录要点 | 证据状态 |
|---|---|---|
| 数据可用性与完备度 | 数据是否需自主爬取，噪声/缺失是否影响交付 | `strong / medium / weak / blocker` |
| 机理物理深度 | 所需专业背景与关键关系是否可获得 | `strong / medium / weak / blocker` |
| 算法计算成本 | 仿真/求解规模是否超出可用算力与赛时 | `strong / medium / weak / blocker` |
| 验证与对标空间 | 是否有与主导风险匹配的验证或参照 | `strong / medium / weak / blocker` |
| 团队技能契合度 | 语言、算法库与调试能力是否覆盖最小可交付实现 | `strong / medium / weak / blocker` |
| 创新与特色空间 | 是否存在有证据支撑的改进空间，而非追求新颖 | `strong / medium / weak / blocker` |

`blocker` 优先触发淘汰或暂停，并记录团队分歧及其证据；`weak`/`medium`/`strong` 也必须写明依据。只有团队先定义权重、刻度和决策用途时，才可附加数值评分；数值评分不替代 blocker 记录或题面约束核对。
